# MMDocIR 멀티모달 문서 검색 프로젝트 계획

현재 목표는 PDF 파싱부터 세 채널 표현·후보 검색·결합·리랭킹·Top 3 오류 분석까지다.
답변 생성, 생성 모델 선정, 생성 답변 평가는 현재 작업 계획에서 제외한다.
기본 커리큘럼인 [RAG_LEARNING_PLAN.md](RAG_LEARNING_PLAN.md)는 그대로 유지한다.
이 문서는 그 커리큘럼과 별도로 프로젝트에서 선택한 모델·방법·프레임워크·실험 범위를 기록한다.
아래 단계는 현재 검색 연구의 실행 순서이며 기본 커리큘럼을 대체하지 않는다.
계획·구현·실측을 구분하며 모델·방법·프레임워크 선택은 근거와 결과에 따라 변경할 수 있다.

## 현재 범위와 확인할 데이터

- 입력과 관찰: [selection.json](../configs/selection.json), [DATA_SPEC.md](DATA_SPEC.md).
- 현재 표본: 영어 PDF 9개 문서·27페이지. 특성별 목적 표본이며 전체 오류율의 무작위 표본이 아니다.
- 전체 PDF로 확대할 때 특성별 선정과 무작위 검토를 병행한다. 자동 점검에서 정상인 페이지도 검토하고, 원본 비교는 문서별 페이지 순서대로 진행한다.
- 데이터셋 revision·배포 스키마·공식 문서/페이지 ID·질의·관련성 라벨·평가 단위는 확인 후 고정한다. 현재 파일명만으로 공식 ID를 만들지 않는다.
- 개인 Coder 컨테이너는 4코어·16GB이며 공용 서버의 GPU·VRAM·모델 지원은 미확인이다. 개인 환경의 한도를 공용 모델 서버의 한도로 간주하지 않는다.

## 단계와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 파싱·구조 보존 | PaddleOCR-VL과 PP-StructureV3 비교 | 원본·좌표·영역·원본 출력·실패 위치가 연결됨 |
| 2 청킹·표현·저장 | 텍스트·페이지/영역 이미지 인코딩과 인덱스 구성 | 모델별 입력·벡터·원본 연결 및 정확 검색을 확인 |
| 3 세 채널·결합 | 채널 역할과 질의 표현 결정, 결합식 비교 | 후보 생성 효과와 점수 결합 효과를 분리해 기록 |
| 4 리랭킹 | 같은 후보의 관련성 재평가 | 적용 전후 정답 보존·순위·비용을 확인 |
| 5 평가·개선 | Recall@3와 모든 문제 질의 분석 | 누락·혼입·최초 실패 단계·개선·재평가를 추적 |

## 모델 선택과 선택 근거를 공부하는 방법

| 역할 | 현재 상태 |
|---|---|
| 파싱 비교 | **PP-StructureV3와 PaddleOCR-VL 선택**. VL은 v1.6 코드 작성 중이며 비교 어댑터는 미구현 |
| 파싱 실행 | **PaddlePaddle 사용 방향 유지** |
| PP-StructureV3 문자 OCR | **PP-OCRv6 medium 검출·인식 연결 계획**. 현재 패키지와 통합 미검증 |
| PP-StructureV3 수식 인식 | 정확한 하위 모델 미정. 문자 OCR 모델과 분리해서 선정 |
| 텍스트 임베딩 | **Qwen3-Embedding-8B 우선 후보**. 최종 선택으로 단정하지 않음 |
| 이미지 임베딩 | **Qwen3-VL-Embedding-8B 선택** |
| 세 번째 표현 채널 | 역할·모델·질의 표현 미정. DINOv3는 검토 후보 |
| 리랭커·DB | 미정. 다룰 입력 모달리티와 실패 유형을 확인한 뒤 선정 |
| 연결 프레임워크 | **LangGraph + 필요한 LangChain 구성 요소 선택**. 실행 상태·경로 제어와 검색/모델 연결의 역할을 분리 |

각 후보는 다음 연결로 설명하고 기록한다.

1. 해결할 실패 유형과 같은 평가 조건에서의 공개 품질 근거.
2. 입력 → 전처리 → 내부 표현 → 출력과 학습 목표.
3. 대안과 다른 구조·학습 데이터·검색 방식. 구조 변경의 인과 효과와 해석·가설을 구분.
4. 프롬프트·해상도·잘림·pooling·정규화·차원·양자화·후처리 등 개선 지점.
5. 프로젝트 실측의 Recall@3·오검색·지연·메모리·재현 조건. 현재 접근 가능성만으로 후보를 정하지 않음.

### 파싱 비교의 의미

PP-StructureV3는 레이아웃·문자 OCR·표·수식 등의 하위 모듈을 연결한다.
PaddleOCR-VL은 영역 분석과 VLM 기반 인식을 연결한다. 같은 전체 페이지를 넣은 최종 품질과 개별 인식의 품질을 구분한다.
PP-StructureV3가 수식에서 더 좋을 것이라는 관찰·가설을 검증하며 어느 파서도 다른 파서의 정답 판정기로 쓰지 않는다.
PaddlePaddle은 실행 프레임워크다. 모델의 정확한 ID·설정과 별개로 수식 품질의 근거로 삼지 않는다.
[PP-StructureV3 공식 문서](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/PP-StructureV3.html)

### Qwen3-VL-Embedding-8B: 선택 이유·내부 동작·대안

선정 문제는 캡션/OCR에 남지 않은 문서 이미지 정보 때문에 텍스트만으로 관련 페이지를 놓치는 것이다.
멀티모달 지원만으로 다른 모델보다 우수하다고 판단하지 않는다.

**내부 흐름**

```text
페이지/영역 이미지
 → 전처리·16×16 패치
 → ViT 시각 특징
 → 2×2 공간 병합·언어 공간 연결
 → 텍스트 토큰과 함께 Qwen3-VL 처리
 → 마지막 유효 토큰의 최종 내부 표현
 → L2 정규화
 → 입력당 최대 4096차원 단일 검색 벡터
```

질의도 같은 임베딩 모델로 독립 인코딩한다. 미리 저장한 문서 벡터와 내적/코사인으로 검색하며 후보마다 질의와 문서를 함께 읽는 리랭커와 구분한다.
[공식 구현](https://github.com/QwenLM/Qwen3-VL-Embedding/blob/main/src/models/qwen3_vl_embedding.py)의 `_pooling_last`는 attention mask로 마지막 유효 위치를 선택한다. README는 EOS 표현으로 설명한다.
[설정](https://huggingface.co/Qwen/Qwen3-VL-Embedding-8B/blob/main/config.json)의 언어 모델은 36층·hidden size 4096이고, DeepStack 시각 특징 인덱스와 공간 병합 설정을 포함한다.
DeepStack은 여러 시각 층의 특징을 언어 처리에 전달한다. 이 구조는 시각 세부 정보 활용을 설명하지만 자체로 우월성의 인과 증명은 아니다.
[기반 모델의 구조 설명](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct)

**학습과 공개 품질 근거**

일반 VLM의 내부 벡터를 그대로 쓰는 방식과 달리 검색용 대조 학습을 거친다.
[기술 보고서](https://arxiv.org/abs/2601.04720)에서는 정답 쌍 정제·어려운 오답 채굴, 단계별 학습, 리랭커 증류와 모델 병합을 설명한다.
검색 시 리랭커를 반드시 호출해야 한다는 뜻은 아니다. 증류는 학습 과정에서 리랭커의 판단을 임베딩 모델에 전달하는 방식이다.

[공식 모델 카드](https://huggingface.co/Qwen/Qwen3-VL-Embedding-8B)의 MMEB-V2 비교표에서 다음 수치를 확인했다. 이는 개발팀 공개 결과이고 본 프로젝트 Recall@3가 아니다.

| 모델 | VisDoc Overall | VDRv1 | VDRv2 | VisDoc OOD |
|---|---|---|---|---|
| Qwen3-VL-Embedding-8B | 83.3 | 88.2 | 69.9 | 78.3 |
| Qwen3-VL-Embedding-2B | 80.2 | 85.2 | 66.0 | 74.3 |
| GME-7B | 79.3 | 89.4 | 55.6 | 68.3 |

크기·접근성보다 문서 검색의 공개 품질을 우선해 8B를 선택했다.
하지만 GME-7B가 VDRv1에서 더 높으므로 모든 문서·항목에서 우세하다는 결론은 내리지 않는다.
논문의 2B 학습 단계 비교에서는 증류가 검색 항목을 개선하는 한편 다른 항목과 상충하고 병합이 이를 조정하는 양상을 보인다.
이를 8B의 모든 구조 요소에 대한 개별 인과 실험으로 확대하지 않는다.

| 대안 | 내부 동작에서 다른 점 | 현재 선택과의 관계 |
|---|---|---|
| CLIP·SigLIP 계열 | 이미지와 텍스트를 별도 인코딩해 정렬하는 dual-encoder 구성 | VLM 처리와 검색용 학습을 갖춘 후보를 우선하되, 구조만으로 문서 검색의 일괄 우열을 주장하지 않음 |
| ColPali 계열 | 토큰·패치별 여러 벡터를 유지하고 국소 대응을 late interaction으로 점수화 | 작은 표 셀·수식 등에서 단일 벡터 압축의 손실이 확인되면 비교할 대안 |
| DINOv3 기본 백본 | 시각 특징을 학습하며 임의의 텍스트 임베딩과 정렬된 상태는 아님 | 텍스트 질문의 대응 표현 없이 세 번째 축으로 붙이지 않음. dino.txt 같은 별도 텍스트 정렬 구성은 구분 |
| Qwen3-VL-Embedding-2B | 같은 계열의 작은 구성으로 단일 벡터 출력 | 비용 비교 목적이면 검토 가능하나 학습상 필수 기준선으로 강제하지 않음 |

개선을 위해서는 이미지 해상도·시각 토큰 예산, 전체 페이지/영역 입력, 실제 입력 잘림, 지시문, pooling·정규화, MRL 차원 축소와 임베딩 양자화를 확인한다.
모델의 지원 한도와 래퍼의 기본 `max_length`를 구분한다. 해상도를 무조건 높이는 대신 세부 정보 보존·검색 품질·메모리·지연을 함께 측정한다.
같은 4096차원인 Qwen3-Embedding 벡터와 직접 내적하지 않는다. 채널별 질의/문서 점수를 공통 후보 ID에 연결한다.

### 프레임워크 비교와 LangGraph·LangChain 선정

세 프레임워크 모두 검색만 실행할 수 있으며 프레임워크 선택 자체가 모델 품질을 높인다는 근거는 없다.
현재 요구는 세 채널 실행·공통 후보 매핑·직접 결합식·리랭킹·중간 점수와 오류 기록이다.

| 항목 | Haystack | LlamaIndex | LangChain |
|---|---|---|---|
| 중심 추상화 | 입출력 socket을 연결한 Component/Pipeline 그래프 | Document→Node, Index·Retriever·NodeWithScore | Document·Retriever와 Runnable 조합 |
| 실행 흐름 | 컴포넌트 의존 관계에 따라 실행, 비동기 분기 가능 | Retriever가 노드/점수를 반환하고 Postprocessor로 처리 | Sequence는 순차 실행, Parallel은 같은 입력으로 경로별 실행 |
| 직접 결합식 | custom component로 후보별 채널 점수를 받아 계산 | custom retriever/postprocessor로 계산 | RunnableLambda 또는 custom retriever로 계산 |
| 제공 결합 도구 | DocumentJoiner의 merge·RRF 등 | QueryFusionRetriever의 결합 모드 | EnsembleRetriever의 weighted RRF |
| 원본 연결 | Document ID·meta를 프로젝트 ID와 연결 | Node ID·metadata·원문/부모 관계를 연결 | Document metadata의 안정된 후보 ID를 명시 |
| 중간 결과 | 컴포넌트 출력 선택·debugging 기능과 직접 로그 | NodeWithScore와 단계별 계측 | Runnable 중간 출력·callbacks/이벤트와 직접 로그 |
| 현재 주의점 | 기본 score 한 값에 채널별 근거를 덮어쓰지 않음 | QueryEngine 대신 Retriever 사용. 질의 확장의 LLM 호출·후보 예산을 명시 | Retriever가 원점수를 항상 반환한다고 가정하지 않음. classic·core·통합 패키지 구분 |

선택한 구성은 LangGraph로 상태·실행 경로를 관리하고 필요한 LangChain 구성 요소를 활용하는 방식이다.
검색 결과에 따라 실행 채널·후보 수·반복·종료를 바꾸는 정책을 독립적인 실험 변수로 다루기 위해 선택했다.
LangGraph의 State는 질의·후보 참조·점수·경로 이력·반복 횟수·사용 예산·종료 이유를 보존하고, Node는 작업을 수행하며 조건부 Edge는 다음 작업을 결정한다.
상태 reducer는 변경분의 누적·교체 규칙이고 검색 점수의 Fusion은 별도 함수다. 병렬 경로의 상태 병합과 중복 정책을 명시한다.
LangChain의 검색기·모델·저장소 인터페이스는 필요한 곳에만 사용한다. Qwen 이미지 임베딩·Paddle 파서·제곱합은 모델별 지원을 확인하고 직접 작성한 어댑터로 연결할 수 있게 한다.
핵심 수학·후보 ID·평가·원점수 보존은 프레임워크에 독립적인 Python 함수/자료구조로 유지한다.
체크포인트의 재개·분기 기능은 같은 중간 상태에서 이후 정책을 비교하는 데 활용한다. 이후 노드의 재실행은 동일한 결과를 보장하지 않으므로 입력·모델·인덱스·캐시·난수·정밀도를 함께 고정한다.
실험 간 설정 변경과 한 질의 안의 적응형 실행을 구분하고 후보 예산·실제 비용을 함께 측정한다. 경로 판단은 추론 시 이용 가능한 신호만 사용하고 평가 정답은 누출하지 않는다.
Haystack은 컴포넌트 입출력 중심의 유력한 대안이며 반복·분기·스냅샷 재개도 지원한다. 기능 유무나 프레임워크 자체의 검색 품질 우위를 선택 근거로 삼지 않는다.
상태·체크포인트·어댑터를 직접 관리할 부담을 기록하고, 4코어·16GB에서 모델 병렬 로딩을 무조건 활성화하지 않는다. 아직 설치·통합 실행은 하지 않았다.

LlamaIndex는 청크와 원문/부모 관계, 계층 검색·문서 인덱싱이 중심이면 특히 유력하다.
LangChain은 기존 통합 도구나 향후 상태 기반 도구 호출이 중심이면 유력하며, 현재도 Runnable만으로 검색 실험을 구성할 수 있다.
두 후보도 구현 가능하므로 기능 부재를 이유로 배제하지 않는다. LangGraph 선택은 실행 제어를 위한 것이며 생성 에이전트나 답변 생성을 추가하는 결정이 아니다.

공식 `QueryFusionRetriever`에는 LLM을 이용한 질의 확장 경로가 있다. 불필요한 질의 생성 없이 원질의만 사용할 설정·초기화 동작을 확인한다.
`EnsembleRetriever.weights`는 원래 코사인 점수의 weighted sum이 아니라 weighted RRF에 사용된다.
어떤 도구를 쓰든 중복 제거 기준은 문자열만이 아니라 실제 공통 후보 ID로 고정하고, 결합 후 점수 외에 원점수와 순위를 별도 보존한다.

## Step 2 청킹·텍스트 및 이미지 임베딩·저장

검색 단위와 임베딩 모델을 데이터에 맞게 선정한다. 듀얼 인코더는 질문과 문서를 각각 인코딩해 벡터로 비교하는 구조이며, 가중치는 공유하거나 별도로 둘 수 있다.

### 청킹 실험

- 고정 길이와 구조 기반 분할을 비교한다. 청크를 원본과 연결하고 제목·조건·예외를 보존한다. 생성한 요약·질문은 원문과 구분한다.
- 크기 256/512/1024 토큰, 겹침 0/10/20% 등을 비교한다. 한 변수씩 바꾼 뒤 유망한 조합을 확인한다.
- 모델의 입력 한도와 토크나이저를 확인한다. 제목·헤더·지시문을 포함한 실제 입력의 잘림을 기록한다.

### 임베딩과 듀얼 인코더 실험

- 텍스트는 Qwen3-Embedding-8B를 우선 후보로 검토하고 이미지는 선택한 Qwen3-VL-Embedding-8B로 구성한다. 모델 개수를 채우기 위한 후보 추가를 강제하지 않는다. 언어·도메인 용어·번호·약어·부정 표현과 시각 질의를 포함한다.
- 이미지 입력은 전체 페이지와 영역 crop을 구분하고 PDF·페이지·좌표·이미지 해시·본문·캡션 연결을 보존한다. 원문 캡션과 생성 설명을 구분하고 벡터만 저장하지 않는다.
- 같은 모델의 질의와 문서를 독립 인코딩한다. 여러 모델의 벡터를 저장하는 것과 한 모델의 토큰별 다중 벡터를 구분한다.
- 모델별 질문·문서용 프롬프트와 인코딩 방식을 적용하고 설정 누락의 영향을 비교한다.
- 모델마다 문서·질문을 다시 임베딩하고 인덱스를 분리한다. 차원이 같아도 다른 모델의 벡터를 섞지 않으며, 거리 함수·정규화를 기록한다.

### 비교할 지표와 선정 근거

| 비교 대상 | 기록할 내용 |
|---|---|
| 청킹 | 핵심 근거 보존, 청크 수와 길이, 중복, 입력 잘림 비율 |
| 검색 품질 | 근거 Recall@k, MRR, nDCG와 질문 유형별 결과 |
| 모델 비용과 제약 | 문서·질문 인코딩 시간, 저장 크기, 호출 비용, 입력 한도 |

같은 근거 라벨에 대한 검색 성능을 비교한다. 모델별 유사도 점수의 절대값은 직접 비교하지 않는다. 정확 벡터 검색을 기준으로 보면 임베딩 품질과 근사 인덱스의 누락을 구분하기 좋다.

### 저장·인덱스 후보 비교

| 항목 | 실습과 확인 내용 |
|---|---|
| 벡터와 거리 함수 | 같은 벡터·거리 함수·정규화·필터로 비교한다. 차원·모델·버전도 확인한다. |
| 정확 검색과 ANN | 정확 검색 결과를 보관하고, 근사 최근접 이웃 검색인 ANN의 누락과 시간 변화를 비교한다. |
| 메타데이터 필터 | 부서·버전·시행일 필터를 적용한다. 조건에 맞는 근거의 누락과 결과 개수를 확인한다. |
| 추가와 수정 및 삭제 | 같은 문서 재처리, 문서 개정, 삭제, 중단 후 재개를 실행한다. 중복과 오래된 청크 잔존 여부를 점검한다. |

DB 제품과 비교 개수는 미정이다. 같은 벡터·거리·필터·검색 범위에서 동작을 비교하고, 프레임워크와 DB를 하나의 선택으로 취급하지 않는다.

### 근거 검색 품질과 ANN 구분

- 근거 Recall@k: 필요한 정답 근거를 얼마나 찾았는지 확인한다.
- ANN 이웃 일치율: 동일한 필터·거리 조건에서 정확 벡터 검색의 상위 k개를 ANN이 얼마나 재현하는지 확인한다.
- k와 탐색량: 결과 개수 k와 HNSW 탐색량은 별개다. 한 변수를 고정하고 다른 변수를 바꿔 비교한다.
- ANN이 정확 검색을 잘 재현해도 정답 근거를 찾았다는 뜻은 아니다. 소규모 데이터에서는 전수 검색이 실행될 수 있으므로 실제 인덱스 사용 여부도 확인한다.

## Step 3 세 채널 표현·후보 검색·결합

### 가져올 설계와 수학적 범위

Tri-CHEF에서 가져올 부분은 세 채널을 분리 보존하고 채널 내부의 질의–문서 점수를 결합하는 설계다.
Re·Im·Z라는 이름만으로 독립성·직교성·새 정보가 생기지 않는다. L2 정규화와 직교화를 구분한다.
세 번째 채널은 추가 정보·모델·질의 인코딩이 결정되어야 활성화한다. 그림 전용 모델에 텍스트 벡터를 임의로 대응시키지 않는다.

[Tri-CHEF v1.1 원문 §III-C·E](https://zenodo.org/records/20046344/files/Tri-CHEF_paper_v1.1.pdf)의 문서 경로는 채널 내부 코사인 A·B·C를 다음처럼 결합한다.

```text
S(q,d) = sqrt(A² + (αB)² + (βC)²)
```

이는 실수 점수의 제곱합이며 엄밀한 복소수 Hermitian 내적·위상 계산과 동일하지 않다.
원문에서는 이 dense 점수의 순위와 sparse 등의 순위를 RRF로 결합하는 별도 단계도 등장한다.
현재 가져오기로 한 것은 세 채널 표현·결합 아이디어이며 전체 시스템이나 기존 모델 조합을 복제하는 것은 아니다.

### 비교군과 통제 조건

| 비교 | 고정할 조건 | 확인할 효과 |
|---|---|---|
| 한 채널 / 두 채널 / 세 채널 | 평가 단위·총 후보 예산·최종 K | 추가 정보의 정답 복구와 오답 유입 |
| 단순 합산 / 정규화 weighted sum / RRF / 제곱합 | 같은 채널·후보 합집합·검색 범위 | 결합법만의 효과 |
| 점수 전처리·음수 처리 변경 | 모델·후보·나머지 결합 설정 | 부호 손실·척도·극단값 영향 |
| 검색 예산을 늘린 단일 경로 | 같은 비용 또는 후보 예산 | 채널 추가 효과와 예산 증가 효과 구분 |

- 각 모델은 자기 채널의 질의·문서만 비교한다. 차원 일치만으로 모델 간 내적·Gram–Schmidt를 수행하지 않는다.
- 페이지·영역·청크 결과를 공통 평가 단위로 매핑하고 원본 ID·표현 단위·중복 정책을 기록한다.
- 후보 합집합에서 점수합·제곱합에 필요한 모든 채널 점수를 계산한다. 미계산과 실제 채널 부재를 분리하고, 미계산 값을 임의의 0으로 채우지 않는다.
- 음수 코사인을 제곱하면 +0.8과 -0.8이 같은 크기로 기여한다. 원점수 분포와 음수 처리 정책을 확인하고 개발 데이터에서 비교한다.
- 제곱합이 특정 채널의 지배·노이즈를 자동 방지한다고 가정하지 않는다. 제곱근은 단조 증가이므로 같은 비음수 제곱합에 대한 순위 자체는 바꾸지 않는다.
- RRF는 `sum_i w_i/(c+rank_i)`이며 순위는 1부터, 목록에 없는 후보는 기여 0이다. c·경로 가중치와 후보 수는 별개다.
- 결합 가중치·정규화·RRF 상수·후보 예산은 미정이며 최종 평가 질의로 조정하지 않는다.

## Step 4 리랭킹·최종 Top 3

리랭커는 질문과 후보의 실제 내용을 함께 읽고 관련성을 다시 평가한다.
텍스트 리랭커에 텍스트 설명만 넣은 경우와 원본 이미지를 받는 멀티모달 리랭커를 구분해 선정한다.
현재 리랭커 모델은 미정이며 일반적인 리랭킹은 후보 밖의 정답을 새로 찾지 못한다.

```text
원질의 → 경로별 후보 → 공통 단위 매핑·결합
      → 동일 후보에 리랭킹 적용/미적용 → 중복 정책 적용 → Top 3
```

- 경로별 검색 수와 리랭커 입력 수는 개발 실험에서 정하고 최종 K=3과 구분한다.
- 같은 후보 집합에서 적용 전후의 정답 포함·순위·불필요한 결과와 지연·메모리를 비교한다.
- 헤더·각주·조건·예외·부정·단위와 이미지 참조가 입력에서 사라지지 않는지 확인한다.
- 입력 토큰·시각 토큰 잘림, 모델별 입력 형식, 점수 방향, 후보별 오류와 타임아웃을 기록한다.
- 정답은 올랐지만 다른 정답이 Top 3 밖으로 밀렸는지, 같은 원본의 중복이 상위를 채웠는지 확인한다.
- 질의 재작성·확장·분해를 도입하면 별도 실험으로 표시한다. 원질의 보존·후보 예산 증가·호출 비용을 함께 기록한다.

## Step 5 Recall@3·질의별 오류 분석·개선

### 관련성 판정과 지표

실제 질의와 라벨을 확인한 뒤 페이지/영역/청크 중 평가 단위와 중복 정책을 고정한다.
문서/페이지가 평가 단위인데 같은 페이지의 청크 여러 개를 별개의 정답으로 세지 않는다.
라벨이 불완전할 수 있으므로 미판정 후보와 명백히 무관한 후보를 구분한다.
G(q)는 질의 q의 관련 항목 집합, R3(q)는 중복 제거 후 상위 최대 3개다.

```text
Recall@3(q)    = |R3(q) ∩ G(q)| / |G(q)|
Precision@3(q) = |R3(q) ∩ G(q)| / 3
Hit@3(q)       = 1 if R3(q) ∩ G(q) is nonempty, else 0
MRR           = mean_q(1 / rank_of_first_relevant(q)); no hit contributes 0
DCG@3(q)      = sum_r=1..3 (2^rel_r - 1) / log2(r+1)
nDCG@3(q)     = DCG@3(q) / IDCG@3(q)
```

MRR을 후보 전체에서 계산하는지 Top 3에서 절단하는지 명시한다. 절단하면 MRR@3로 표시한다.
rel은 확인한 관련성 등급이며 이진 라벨이면 0/1이다. IDCG는 같은 라벨로 가능한 이상적 순위의 DCG다.
관련 집합이 비어 Recall·nDCG를 정의할 수 없는 질의는 별도 집계한다.
관련 항목이 3개보다 많으면 Recall@3의 최대값은 3/|G(q)|다.
3개 미만 반환에도 고정 슬롯 Precision@3의 분모는 3으로 두고 실제 반환 수를 함께 기록한다.

정답이 A 하나이고 [A,X,Y]를 반환하면 Recall@3는 1이어도 무관한 결과 2개가 있다.
따라서 정답 누락뿐 아니라 혼입도 분석한다. 빈 결과·실패·타임아웃을 성공한 문항 평균에서 조용히 제외하지 않는다.

### 모든 문제 질의의 기록

| 항목 | 기록할 내용 |
|---|---|
| 질의 | ID·원문·유형·분할·관련성 라벨 버전 |
| 정답과 후보 | 관련 항목, 경로별 후보, 결합 전후·리랭킹 전후 순위, 최종 Top 3 |
| 점수 | 채널별 원점수·정규화 값·채널 부재·최종 점수·가중치·기여도 |
| 문제 | 누락된 정답·혼입된 후보·중복·잘못된 원본 매핑 |
| 원인 | 최초 실패 단계·실제 관찰 증거·아직 검증하지 않은 원인 가설 |
| 개선 | 바꿀 변수·비교군·개발 데이터 재평가·개선과 퇴행 사례 |
| 출처·비용 | 원본 문서·페이지·영역·벡터·코드/모델 버전, 시간·메모리·호출 비용 |

### 처음 실패한 단계 찾기

| 관찰 | 우선 확인할 부분 |
|---|---|
| 원본 정보가 파싱 결과에 없음 | 파서·OCR·수식 검출과 인식·읽기 순서 |
| 파싱에는 있으나 청크·crop에서 관계가 끊김 | 분할·헤더·주변 근거·이미지 경계 |
| 표현은 있으나 정확 검색 후보에도 없음 | 질의/문서 인코딩·지시문·잘림·검색 범위·후보 수 |
| 정확 검색에는 있으나 ANN에서 없음 | 탐색량·필터·인덱스 설정 |
| 경로별 후보에는 있으나 결합 후 없음 | 공통 ID·척도·음수 처리·가중치·결합식 |
| 결합 후 정답이 리랭킹에서 하락 | 모델 적합성·입력 누락/잘림·점수와 정렬 |
| 후보는 맞지만 Top 3가 중복으로 채워짐 | 평가 단위·중복 제거·다양성·복수 근거 보존 |

개발과 최종 평가를 문서 단위로 분리하고 중복을 확인한다. 한 번에 바꾸는 변수를 통제한다.
최종 평가 오류는 분석할 수 있지만 그 질의에 반복적으로 설정을 맞춘 결과를 최종 일반화 성능으로 보고하지 않는다.
전체 평균과 질의 유형별 문항 수·정답 누락·혼입·퇴행을 함께 보고한다.

## 실행·재현·다음 구현

- 현재 파싱 모듈의 오타·변수·JSON 변환·좌표를 점검하고 저장·실행 진입점을 연결한다. 실제 작성·수정은 별도 코드 작업 범위에서 수행한다.
- 원본 위 영역 표시, 모델 원본 출력, 공통 객체와 수식 비교 자료를 연결한다. 현재 27페이지 실행을 과거 24페이지 실행으로 대체하지 않는다.
- Qwen 이미지 임베딩의 전체 페이지/영역 입력·원본 연결·질의 인코딩을 구성한다. 아직 인코딩·검색을 검증하지 않았다.
- 세 번째 채널과 리랭커·DB를 결정하고 모델별 실행 환경·revision·장치·정밀도를 고정한다. 선택한 LangGraph·LangChain 구성의 상태·경로 정책·어댑터를 구현하고 검증한다.
- 데이터 revision·해시·코드 버전·난수·분할·전처리·모델·후보 예산·결합·시간·메모리 설정을 기록한다.
- 중단 후 재개·문서 추가/개정/삭제 시 누락·중복·오래된 벡터·캐시 잔존을 확인한다.

이 문서는 현재 계획이다. 모델 설치·다운로드·코드 구현·실험 실행을 완료했다는 뜻이 아니다.
