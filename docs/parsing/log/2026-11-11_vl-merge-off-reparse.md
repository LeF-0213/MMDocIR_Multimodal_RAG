실행: 2026-11-10~11. 비교·정리: 2026-11-11. 실행 코드: `dcd68e6`.

PDF → 파싱〔재실행·전후 비교〕 → 청킹 → 임베딩 → 인덱스 → 검색·평가

## 1. 무엇을 확인했나

[파서별 문제 검토](2026-10-30_parser-quality-review.md#문장bbox-불일치의-유력한-발생-경로)에서 VL의 문장–bbox 불일치는
PaddleX의 영역 병합(`merge_layout_blocks=True`)이 유력한 원인이었다. 병합 그룹의 텍스트가 첫 블록에
몰리고 나머지 블록은 빈 문자열로 남는 현상이다. PR #13에서 다음 두 가지를 바꿨다.

- VL: `merge_layout_blocks=False`로 병합을 끈다.
- VL·Structure: 결과 객체의 그림 crop(`markdown_images`, 표 안 그림 포함)을 저장한다.

Structure에는 병합 옵션이 없으므로 이번 재실행에서 바뀐 것은 그림 저장뿐이다.
같은 27페이지를 다시 파싱해, 병합 해제가 빈 블록과 몰린 텍스트를 없애는지와 다른 결과가 바뀌는지 확인했다.

관찰:

- 내용이 바뀐 11페이지는 모두 기준 실행에 병합 그룹이 있던 페이지다. bbox와 라벨은 그대로이고 텍스트만 블록 사이에서 다시 나뉘었다.
- 기준에서는 그룹의 첫 블록이 여러 영역의 텍스트를 함께 가졌고 뒤 블록은 비어 있었다. 새 실행에서는 각 블록이 자기 텍스트를 가진다.
  예: 뉴스 1페이지 블록 19는 기준에서 288자(두 단락이 이어짐)였고 블록 20은 비어 있었다.

- 블록별 텍스트가 해당 bbox 영역의 원문과 맞는지는 위 예시 몇 개만 확인했다. 27페이지 전체를 원문과 대조하지는 않았다.
- Toyota 2페이지의 반복 출력은 그대로다. 한 블록이 2,050단어이고 그중 2,029단어가 "China"다.
  병합을 꺼도 바뀌지 않았으므로 병합이 원인은 아니다. 이후 조사에서 생성 한도 4,096토큰까지 이어진 반복이며,
  입력 해상도를 576 DPI로 올리면 사라지는 것을 확인했다([원인 조사](2026-11-11_vl-generation-limit-repetition.md)).
- Toyota 21페이지의 `partial`도 그대로다. 한 bbox가 PDF 오른쪽 경계를 약 0.11pt 넘은 경고이며 병합과 관계없다.

## 7. 해석과 한계

- 병합 해제로 VL의 빈 text 블록 23개와 병합 그룹 22개가 모두 사라졌다. bbox·라벨·전체 텍스트는 거의 그대로다.
  관찰했던 "한 블록에 여러 영역 텍스트, 옆 블록은 빈칸" 현상은 이 표본에서 재현되지 않는다.
- 블록별 텍스트와 bbox의 대응이 정확한지는 예시 몇 개만 확인했다. 정답 기반 문장 위치 평가는 아직 없다.
- Toyota 2페이지 반복 출력, 슬라이드 6페이지와 Toyota 7페이지 긴 숫자 나열, Structure 표 격자 신호 3건은 병합과 다른 원인이다.
- 같은 이미지·같은 패키지로 다시 실행했지만 실행 기기가 달랐다. 페이지 이미지 해시가 같고 블록 bbox가 그대로라서,
  내용 변화는 기기가 아니라 병합 설정 때문이라고 판단했다. 같은 기기에서 설정만 바꾼 대조 실행은 하지 않았다.
