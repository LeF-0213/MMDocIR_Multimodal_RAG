# VLM이 빨강·파랑 채널이 바뀐 이미지를 받음

- 상태: 미해결. 원인 경로는 확인했고, 전체 품질 영향은 측정하지 않았다.
- 관련 실행: VL 파싱 전체(144 DPI 페이지 이미지를 쓰는 모든 실행)
- 코드: 원인 조사 `8ec2789`(#18)
- 출처: `docs/parsing_log/PARSING_ROOT_CAUSES.md`의 1·2.5·7·8절(커밋 `1655543`)을 옮겨 다시 구성했다.

```text
PDF → 파싱〔VLM 입력〕 → 청킹 → 임베딩 → 인덱스 → 검색·평가
```

## 1. 문제가 어디서 보였나

2026-11-11 [생성 한도 반복](2026-11-11_vl-generation-limit-repetition.md)의 원인을 찾으려고 Toyota p2 블록을
해상도만 바꿔 인식하는 통제 실험을 했다. 첫 실험에서 RGB 배열을 넣었더니 144 DPI 출력이 파이프라인 출력과 달랐다.
입력이 파이프라인과 같지 않다는 신호였다.

## 2. 원인을 어떻게 찾았나 (사실)

- 프로젝트는 PaddleOCR 관례대로 BGR 페이지 배열을 넘긴다(`parsing/pdf_parser.py`).
- PaddleX VL 파이프라인은 이 배열에서 블록을 잘라 색 변환 없이 VLM에 넘긴다.
- 로컬 처리기 `fetch_image()`는 배열을 `Image.fromarray()`로 그대로 읽는다. RGB 순서로 해석한다.
- 그래서 파이프라인에서 VLM은 빨강·파랑 채널이 바뀐 이미지를 받는다.
- BGR 배열로 다시 실험하자 144 DPI 출력이 파이프라인 출력과 같아졌다.

576 DPI 조건에서는 RGB 입력의 텍스트층 재현율(0.89)이 BGR 입력(0.79)보다 높았다. 블록 하나의 결과이므로
채널 순서가 전체 인식 품질에 주는 영향은 판단하지 않는다(추론하지 않음).

## 3. 왜 이 해결책을 골랐나

미적용.

- 당시 후보(원인 조사 8절): VLM 입력을 RGB로 바꾸는 조건과 현재 조건을 같은 27페이지에서 비교한다.
  PaddleX 내부 동작을 바꾸는 일이라 영향 범위를 먼저 확인해야 한다.
- 관련 결정: [생성 한도 블록 재인식](2026-11-11_vl-generation-limit-repetition.md)은 파이프라인과 조건을 맞추려고
  BGR 입력을 그대로 썼다. 바꾸는 변수를 해상도 하나로 묶기 위해서다.

## 4. 결과

미적용.

## 5. 남은 문제와 다음 단계

- VLM이 채널이 바뀐 입력을 받는 것이 PaddleX가 의도한 동작인지 확인하지 않았다. 문서와 학습 조건을 보지 못했다.
- 같은 27페이지에서 RGB와 BGR 조건을 비교하는 실행이 필요하다. 레이아웃 검출 모델도 같은 배열을 받으므로
  VLM 입력만 바꾸는 방법과 전체를 바꾸는 방법의 영향 범위를 나눠 봐야 한다.
