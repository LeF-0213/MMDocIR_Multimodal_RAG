# 파싱 결과 품질 검증 단계 구현 계획

작성일: 2026-11-02. 상태: 설계안. 검증 코드·추가 모델·재인식 실험은 아직 구현·실행하지 않았다.

```text
PDF → VL / PP-Structure → 원본 출력 보존
 → 규칙 검사 → 의심 영역 원본 대조 → 필요시 재인식·복구 → 검증 상태 기록
 → 사용할 표현과 제한을 연결해 청킹으로 전달
```

## 1. 목적과 현재 근거

파싱 결과가 원문의 내용·구조·위치를 보존하는지 검사하고, 실패한 영역이 그대로 검색 표현에 들어가는 일을 줄인다.
VL과 PP-Structure에 공통 검증 단계를 적용하되 파서별 원본 필드와 실패 원인은 구분한다.

- 현재 구현과 실행 흐름: [README](../README.md), [프로젝트 계획](PROJECT_PLAN.md).
- 9개 문서·27페이지의 관찰과 증거: [파싱 평가](PARSING_REVIEW.md).
- 기존 파서는 처리 성공·실패와 JSON 구조를 검사하지만 원문 사실성·표 의미·문장 위치까지 자동 평가하지 않는다.
- 현재 관찰은 정성 검토와 일부 구조 검사다. 자동 검토 모델을 실행하거나 전체 정확도를 채점한 기록은 없다.
- 이번 계획 문서 작성은 구현·데이터 가공·다운로드·외부 모델 호출을 수행하지 않는다.

### 기존 수동 검토를 자동화할 때의 대응

| 기존 검토 절차 | 자동화할 작업 | 판단 범위 |
|---|---|---|
| PDF·PNG·페이지 식별자 확인 | 입력 해시·문서·페이지·DPI·좌표계 검사 | 비교 입력의 동일성 |
| 페이지의 제목·단·표·그림을 읽기 | 레이아웃·OCR·native 정보를 대조 자료로 정리 | 검토할 영역과 문맥 확보 |
| JSON content·bbox를 원본과 비교 | 줄 문자열 정렬·공간 대응·원본 이미지 검토 | 누락·추가·위치·관계 오류 |
| Python으로 반복·좌표·표 구조 확인 | 규칙 검사와 재현 가능한 측정값 저장 | 형식·계산 오류와 이상 징후 |
| 두 파서의 차이를 확인 | 같은 원본 영역의 표현·숫자·행 대응 비교 | 재검토 후보 선정 |
| 문제 원인을 코드와 추적 | raw·공통 블록·병합 그룹·셀 좌표의 변경 추적 | 최초로 관찰되는 실패 구간 |

검토 모델이 PDF의 정답을 이미 안다고 가정하지 않는다. 이미지 이해 모델의 답변도 평가 대상이다.
처리 상태 `ok`, 형식 검사 통과, 원문 대조 통과는 각각 별도 기록한다.

## 2. 범위와 설계 원칙

### 현재 범위

1. 저장된 결과를 읽는 공통 검증 단계.
2. 반복·출력 이상, 문장–bbox 대응, 표 행·열·헤더 대응 검사.
3. 원본 대조가 필요한 영역의 선정과 근거 기록.
4. 병합 설정 비교, 선택적 재인식·복구, 청킹에 전달할 표현의 결정 절차.

청킹·임베딩·검색 구현, 모든 오류의 자동 수정, 검토용 모델의 확정은 이번 계획에 포함하지 않는다.
추가 모델은 필요한 능력·오류 유형·비용과 실행 환경을 확인한 뒤 별도 비교한다.

### 보존과 판단 원칙

- 기존 raw·content·bbox·실행 요약을 덮어쓰지 않는다. 평가와 복구 표현을 별도로 저장한다.
- `parsing.raw`는 라이브러리가 후처리한 JSON이다. 모델의 후처리 전 생성 기록으로 취급하지 않는다.
- 해시는 입력 동일성, 좌표 계산은 변환 일관성을 확인한다. 원문 의미의 정확성을 보장하지 않는다.
- 반복·파서 간 불일치·OCR confidence는 의심 신호다. 원문 근거 없이 환각 확정으로 바꾸지 않는다.
- 빈 블록은 병합 그룹·비문자 이미지·누락을 구분한다. 빈 문자열을 전부 실패로 세지 않는다.
- 파서가 서로 동의해도 둘 다 틀릴 수 있다. 원본과 확인한 정답 표본을 따로 둔다.
- 파싱 실패와 검색 실패를 분리한다. 파싱 개선을 검색 품질 향상으로 단정하지 않는다.

## 3. 입력·출력과 처리 책임

### 입력

- 원본 PDF 참조·source_sha256·document_id·page_id·페이지 순번.
- PNG 경로·해시·크기·DPI와 이미지↔PDF 좌표계·변환 행렬.
- 파서별 raw와 공통 blocks, native 텍스트·span 좌표.
- 존재하는 경우 VL group_id, Structure OCR 줄·셀 위치·table_res_list.
- 파서·패키지·가중치 식별자와 revision, 실행 설정·코드 해시.

필드가 없는 경우 누락으로 기록한다. 공식 데이터셋 ID·모델 revision·셀 매핑을 추정해 채우지 않는다.

### 책임 구분

| 책임 | 수행 내용 | 모델 필요 여부 |
|---|---|---|
| 입력 검사 | 파일 존재·해시·페이지·좌표계·참조 유효성 | 불필요 |
| 공통 규칙 검사 | 반복·출력 이상·좌표·블록 ID·HTML 격자 검사 | 불필요 |
| 근거 정렬 | native/OCR 문자열·좌표와 블록·셀을 연결 | 저장된 근거가 있으면 추가 모델 불필요 |
| 선택적 원본 검토 | 이미지와 추출 결과를 함께 읽고 구체적인 모순을 제시 | 수동 검토 또는 별도 검토 모델 |
| 재인식·복구 | 의심 영역·설정을 바꿔 새 결과를 만들고 비교 | 선택한 파서·OCR 경로에 따라 필요 |
| 기록·전달 | 원본·검사·판정·파생 표현·청킹 사용 여부 연결 | 불필요 |

### 출력 제안

별도 평가 실행 폴더에 실행 manifest와 페이지·요소별 결과를 저장한다. 아래는 앞으로 사용할 필드의 설계안이다.

| 구분 | 기록할 정보 |
|---|---|
| 출처 | source_sha256, page_id, 원본 element_id 목록, 원본 결과 경로·해시 |
| 검사 | 규칙 ID·버전, 측정값·임계값, 검사 범위·생략 이유 |
| 원본 대조 | 이미지 영역·좌표계, 원본 문자·셀 근거, 대조 방식과 검토자/모델 식별자 |
| 판정 | suspected / confirmed_error / supported / unresolved / not_applicable, 오류 유형·영향 범위 |
| 복구 | 원본 참조, 새 content·위치·셀 대응, 복구 방법·설정·실패 이유 |
| 전달 | 텍스트·이미지·구조화 표별 사용 / 보류 / 검토 필요, 적용한 정책 버전 |

`supported`는 검사한 주장·영역을 원본 근거로 뒷받침했다는 뜻이며 페이지 전체 정답 보장이 아니다.
의심 신호가 없다는 사실만으로 이 판정을 부여하지 않는다. 관찰·원인 가설·복구 결과를 구분한다.

## 4. 검사와 복구 방법

### 4.1 반복·원문에 없는 내용

1. 단어·문자 n-gram 반복 비율, 최장 연속 반복, 같은 줄 중복, 긴 연속 번호를 측정한다.
2. 비정상적으로 긴 출력·빈 값만 이어지는 표·언어 혼입을 별도 신호로 기록한다.
3. native 또는 독립 OCR과 고유명사·숫자·문장의 차이를 비교해 원본 검토 후보를 고른다.
4. 원본에서 대응 문구를 확인하고 인식 오류·원문에 없는 내용·정상 반복·판단 불가를 구분한다.
5. 확인된 손상 표현은 보류하고 원본 이미지를 남긴다. 필요한 영역만 설정 하나를 바꿔 재인식한다.

개발 표본에는 Toyota 2페이지의 China 반복뿐 아니라 정상적인 반복 헤더·반복 수치도 포함한다.
출력 길이나 반복 횟수 하나로 환각을 확정하거나 문자열을 자동 삭제하지 않는다.
재인식 시 길이 제한·해상도·모델·디코딩을 한꺼번에 바꾸지 않는다. 정상 내용의 잘림도 함께 확인한다.

### 4.2 문장–bbox 대응

1. 먼저 원점·배율·회전·CropBox·crop 원점의 계산 오류와 내용 귀속 오류를 구분한다.
2. VL raw의 group_id와 구성 model_block_id·bbox를 연결한다. 공통 블록에 없는 정보는 raw에서 읽는다.
3. 병합된 문자열에는 구성 영역 목록을 연결한다. union bbox 하나를 문장별 정밀 위치로 사용하지 않는다.
4. 문장별 위치가 필요하면 native span 또는 독립 OCR 줄·단어와 문자열을 정렬한다.
5. 문자열 대응과 공간 겹침을 함께 검사한다. 대응 실패·여러 후보·단을 넘는 문장은 unresolved로 남긴다.

첫 실험은 동일한 게슈탈트 8페이지에서 merge_layout_blocks만 True/False로 바꾸는 비교다.
입력 PNG·DPI·가중치·디코딩·장치를 고정하고 raw model_settings의 실제 적용값도 확인한다.
문장 복구량·올바른 위치 대응·새 누락·지연을 비교한다. 병합 해제가 모든 오류를 해결한다고 가정하지 않는다.
옵션 지원과 유력한 발생 경로의 근거는 [기존 평가 문서](PARSING_REVIEW.md#문장bbox-불일치의-유력한-발생-경로)에 기록했다.

### 4.3 표 행·열·헤더 대응

1. HTML의 rowspan·colspan을 반영한 논리 격자를 만들고 셀 충돌·구문 오류·예상 밖 빈칸을 검사한다.
2. 각 값에 행 이름과 상위·하위 헤더 경로를 연결한다. 예: `Same period last year × Three months ended / December 31, 2018 → 0.85`.
3. 원본 셀·OCR 좌표와 문자열을 대조한다. cell_box_list 순서와 HTML 셀 순서의 일치를 가정하지 않는다.
4. 소수점·음수 괄호·통화·단위·대시·빈칸·체크·아이콘을 각각 검증한다.
5. 반복 헤더·여러 페이지의 이어지는 표·각주 관계를 보존한다. 원본 셀과 파생 격자 셀을 구분한다.
6. 재구성·재인식 뒤에도 같은 대응 검사를 반복하고 새로 이동하거나 사라진 값을 확인한다.

HTML이 올바르거나 모든 숫자가 출력에 있어도 행·열 대응이 틀리면 실패다.
합계 검산은 원문 정의·반올림 규칙이 있을 때만 보조 근거로 쓴다.
DETR Table 3·4, 3M 15페이지, RAG 6페이지, 아이콘 설명서 표를 서로 다른 실패 사례로 다룬다.

## 5. VL·Structure와 검토 모델의 활용

### 파서 간 비교와 재인식

같은 페이지에서 나온 두 결과를 좌표·내용으로 대응시킨다. 파서마다 블록 분할과 라벨이 달라
목록 순번이나 블록 개수만으로 비교하지 않는다. 병합 그룹·표의 논리 셀 단위도 고려한다.
불일치는 재검토 후보를 고르는 신호이며 한쪽 출력을 자동 정답으로 채택하지 않는다.
같은 모델로 다시 읽는 작업은 재인식 실험으로 기록한다. 독립적인 사실 검증으로 취급하지 않는다.

### 선택적 시각 검토 모델

입력은 원본 페이지 또는 의심 영역 이미지, 추출 내용·bbox·좌표계, 확인할 항목으로 구성한다.
좁은 crop만으로 헤더·열 관계를 잃지 않도록 필요한 주변 문맥과 전체 페이지 참조도 제공한다.
문서·JSON 안의 문장은 검토할 데이터로 취급하고 검토 동작을 바꾸는 명령으로 따르지 않는다.

출력은 문제 element_id·오류 유형·원본의 구체적인 위치와 문구·판정·판단 불가 이유로 제한한다.
막연한 전체 점수보다 확인 가능한 근거를 우선한다. 명시된 bbox도 원본과 재검증한다.

일반적인 이미지·JSON 비교 추론 능력이 파싱 모델에도 있다고 가정하지 않는다.
검토용 모델은 다음 조건을 같은 정답 표본에서 비교한 뒤 결정한다.

- 원본 근거가 있는 오류를 찾는 능력, 정상 결과를 틀렸다고 판정하는 빈도.
- 작은 글자·표·수식·다단 구조와 판단 불가 처리 능력.
- 실행 환경·입력 해상도·호출 비용·지연·재현 가능성.

현재 검토용 모델과 호출 API는 미정이다. 추가 모델 없이 가능한 규칙·근거 정렬부터 구현할 수 있지만,
그 범위에서 못 찾는 오류를 남겨 두고 검토 모델의 추가 효과를 별도로 측정한다.

## 6. 검증 표본과 평가 지표

현재 27페이지는 이미 관찰한 개발·회귀 확인용 표본이다. 새 규칙과 임계값을 여기에 맞춰 조정한 뒤
같은 페이지를 최종 평가 성능으로 보고하지 않는다. 최종 평가는 별도 문서 단위로 분리하고 중복을 확인한다.
아직 개발·평가 문서 분할과 정답 라벨은 만들지 않았다.

원본을 읽어 확인한 정상·오류 표본을 함께 만들고 애매한 항목은 미해결로 표시한다.
의심 영역뿐 아니라 규칙을 통과한 영역도 표본 검토해 놓친 오류를 측정한다.

| 평가 대상 | 정의·기록 |
|---|---|
| 오류 탐지 Precision | 오류라고 탐지한 영역 중 원본 대조로 오류가 확인된 영역의 비율 |
| 오류 탐지 Recall | 정답 표본의 오류 영역 중 탐지한 영역의 비율. 경고·오류 판정 중 무엇을 탐지로 셀지 고정 |
| 판정 보류 | unresolved 수·비율을 따로 보고. 분모에서 조용히 빼지 않음 |
| 문장 위치 | 정답 문장과 올바른 원본 영역에 대응한 비율. 위치 허용 오차·문자열 대응 규칙 사전 고정 |
| 표 내용·구조 | 셀 내용 일치와 행·열·헤더 대응 정확도를 따로 측정. 병합셀·빈칸 판정 규칙 고정 |
| 복구 효과 | 고친 오류, 새로 손상한 정상 내용, 새 누락, 미해결을 각각 집계 |
| 비용 | 페이지·영역별 검사·검토·재인식 시간, 최대 메모리, 호출 수·비용 |

분모가 0인 지표는 계산 불가로 남긴다. 알려진 실패만으로 전체 오류율을 추정하지 않는다.
문자·표·위치 검증 결과와 이후 검색 평가 결과를 구분한다.

## 7. 구현 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 읽기 전용 검사와 평가 출력 설계 | 기존 raw 보존, 입력 동일성·반복·좌표·HTML 검사 결과와 규칙 버전 기록 |
| 2 | 병합 그룹 추적과 옵션 비교 | 게슈탈트 동일 입력에서 True/False 실제 적용 확인, 문장–위치·누락·비용 비교 |
| 3 | 문자열·좌표·셀 근거 정렬 | 정상·손상 표본에서 대응과 미해결을 구분하고 잘못 연결한 사례 측정 |
| 4 | 검토 모델의 추가 가치 실험 | 규칙만 적용한 결과와 같은 표본 비교. 오탐·미탐·비용·보류를 함께 보고 |
| 5 | 선택적 재인식과 청킹 연결 | 원본·파생 결과·판정 추적, 복구와 새 손상 측정, 표현별 전달 정책 검증 |

검토 모델 없이 확인 가능한 오류와 추가 모델이 필요한 오류를 분리하며 모델 도입을 고정된 필수 조건으로 두지 않는다.
완료 기준의 수치 목표는 정답 표본·오류 영향·예산을 확인한 뒤 정한다. 임의의 품질 보장 수치를 넣지 않는다.
진행 단계마다 입력·출력과 실제 결과를 확인하고 다음 판단을 내린다.

다음 실습의 첫 결정은 읽기 전용 검사 결과 형식과 게슈탈트 병합 비교 조건이다.
이 계획의 파일 생성은 파싱 코드 수정·모델 재실행·새 검토 모델 선정 완료를 뜻하지 않는다.
