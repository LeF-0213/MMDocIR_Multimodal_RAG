# VL 재파싱 중 컨테이너가 외부에서 종료됨

- 상태: 미해결. 실행은 재개로 끝냈고, 종료한 주체와 이유는 확인하지 못했다.
- 관련 실행: [parsing_vl_20261110T233124280038Z](../../../outputs/parsing_vl_20261110T233124280038Z)(`resume/segment_2/`에 재개 구간)
- 코드: 재개 기능 PR #14 이후, 재개 때 비교 기준 유지 `927c687`(#16)
- 출처: `docs/parsing_log/PARSING_ROOT_CAUSES.md` 5·7·8절과 `docs/parsing_log/REPARSE_RESULT.md` 2절(커밋 `1655543`)을 옮겨 다시 구성했다.

## 1. 문제가 어디서 보였나

병합 해제 VL 재파싱이 시작 47분 뒤(2026-11-11 00:18 UTC) 외부 종료 신호(SIGTERM)로 끊겼다. 4페이지를 저장한 상태였다
([병합 해제 재파싱](../../parsing/log/2026-11-11_vl.md) 1.2절).

## 2. 원인을 어떻게 찾았나

- 사실:
  - 파싱 프로세스는 00:18:35 UTC에 SIGTERM을 받았다. Paddle 로그에 남은 보낸 PID는 0이다. 컨테이너 안의 다른
    프로세스가 보냈다면 그 PID가 남으므로, 커널이나 컨테이너 밖에서 온 신호다.
  - 같은 00:18:35~36에 관계없는 다른 프로그램도 홈 폴더에 종료 상태 파일을 썼다. 그다음 파일 활동은 00:34:42다.
    컨테이너 전체가 이때 종료됐다.
  - Coder 빌드 기록에는 00:18 무렵 빌드가 없다. 00:33:52 정지(빌드 #8)에서 Terraform이 Docker 컨테이너를
    `Drift detected (delete)`로 보고했다. Coder가 정지하기 전에 컨테이너가 이미 없었다.
    00:33:54 시작(빌드 #9)에서 새 컨테이너를 만들었다. 02:07:52 정지·02:07:54 시작(빌드 #10·#11)도 있었다.
  - 워크스페이스에는 자동 정지(TTL)와 자동 시작 일정이 없다(`coder schedule show`).
- 추론: 컨테이너는 Coder 밖, Docker 호스트 쪽 작업으로 종료·삭제됐다. 정전 뒤 복구 작업이나 호스트 Docker 재시작을
  의심하지만, 호스트 로그를 볼 권한이 없어 확인하지 못했다. Coder 자동 정지는 일정이 없으므로 원인에서 뺐다.

## 3. 왜 이 해결책을 골랐나

- 원인 대응: 미적용. 호스트 로그 권한이 없어 대응할 수 없다.
- 실행 대응: `main.py --resume`으로 같은 폴더에서 재개했다. 저장된 4페이지는 다시 추론하지 않았다.
  이미 있던 기능이라 새로 고를 방법이 없었다.

## 4. 결과

- 재개로 27페이지를 끝냈다. 재개 때 처음 지정한 비교 기준이 이어지지 않아 자동 비교가 생략됐고, 비교 보고서는 손으로 만들었다.
  이 문제는 PR #16에서 고쳤다.
- 재개 구간의 메모리 원시 로그 `resume/segment_2/resources.jsonl`(88,184,804바이트)은 커밋하지 않았다
  (SHA-256 `d5be00348cd5d8af06ba562bde0ce920369f24a584c04bc168f649ca7f6e59c0`). 최대 RSS 집계는 실행 폴더의
  `experiment_finished.json`에 있다.

## 5. 남은 문제와 다음 단계

- 컨테이너를 종료한 주체와 이유: Docker 호스트 로그 접근 권한이 필요하다.
- 긴 실행은 언제든 끊길 수 있다고 보고 재개 기능을 전제로 실행한다.
