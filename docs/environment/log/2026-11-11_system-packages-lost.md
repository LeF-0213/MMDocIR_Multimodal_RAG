# 컨테이너를 다시 시작하면 apt로 설치한 시스템 라이브러리가 사라짐

- ID: E-03
- 상태: 미해결. 재시작할 때마다 다시 설치한다.
- 관련 실행: 2026-11-11 컨테이너 재시작 뒤의 모든 실행
- 출처: `docs/parsing_log/PARSING_ROOT_CAUSES.md` 1·6·8절(커밋 `1655543`)과 루트 README 실행 준비 절을 옮겨 다시 구성했다.

## 1. 문제가 어디서 보였나

2026-11-11 컨테이너가 다시 시작된 직후([컨테이너 종료](2026-11-11_container-termination.md)) `ldconfig -p`에서
`libGL.so.1`이 0건이었다. 2026-11-08에 설치한 시스템 라이브러리가 없어진 것이다. 이 라이브러리가 없으면
`import cv2`가 실패한다(2026-11-08 처음 설치할 때 확인).

## 2. 원인을 어떻게 찾았나 (사실)

- Coder는 워크스페이스를 시작할 때마다 같은 이미지(`workspace-base@sha256:fc0b37e1…`)에서 새 Docker 컨테이너를 만든다
  (빌드 #9·#11 기록).
- 홈 폴더(저장소·`.venv`·모델)는 남는다. 하지만 `sudo apt-get`으로 설치한 `libgl1`·`libglib2.0-0t64`는 이전 컨테이너의
  쓰기 계층에 있었으므로 함께 사라진다.
- 다시 설치하자 `cv2` 4.10.0을 불러왔다.

## 3. 왜 이 해결책을 골랐나

- 당시 후보(원인 조사 8절): 이미지나 시작 스크립트에 시스템 패키지를 넣는다. Coder 템플릿 관리자 권한이 필요하다.
- 현재: 권한이 없어 미적용. 재시작할 때마다 `sudo apt-get install libgl1 libglib2.0-0t64`로 다시 설치한다(루트 README 실행 준비).

## 4. 결과

미적용.

## 5. 남은 문제와 다음 단계

- Coder 템플릿 관리자에게 이미지·시작 스크립트에 두 패키지를 넣도록 요청해야 한다.
