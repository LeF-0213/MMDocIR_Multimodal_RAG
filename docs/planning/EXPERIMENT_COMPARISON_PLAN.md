# 단계별 실행 기록과 전후 비교 구현 계획

최초 작성일: 2026-11-04. 구현 상태 갱신: 2026-11-05. 설계 당시 코드 확인 기준: `0fe85bc`.
이 문서는 대화에서 정한 프로젝트별 구현 계획이며 [기본 학습 커리큘럼](RAG_LEARNING_PLAN.md)과 구분한다.
공통 실행 기록·소스 diff·모델 파일 목록·메모리 관측과 정답을 입력받는 파싱 전후 평가를 구현했다.
현재 지원 범위·설정·실행 명령·한계는 [사용법](EXPERIMENT_COMPARISON_USAGE.md)에 기록했다.
파싱 공통 기록은 기본 활성화하고, 같은 파서·선정 범위의 최근 종료 실행을 시작 시 고정해
종료 후 자동 비교한다. 기준이 없는 첫 실행의 생략과 기록/비교 끄기 옵션도 구현했다.
루트 `main.py`는 `configs/parsing_run.json`을 읽어 로컬·HTTP 입력과 기존 파싱 진입점을 연결한다.
매번 긴 명령을 작성하지 않고 같은 설정으로 파싱·기록·비교를 실행한다.
실제 원문 정답 작성·개선 모델 재추론·품질 개선 측정과 후속 단계의 평가기는 아직 미구현·미실행이다.
아래 절은 전체 설계와 확장 목표이며 모든 세부 기능의 구현 완료를 뜻하지 않는다.

## 1. 목표와 현재 위치

```text
인덱싱: PDF → 파싱·검증 → 청킹 → 임베딩 → 저장·인덱싱
검색: 질문 → 후보 생성·확장·결합 → 리랭킹 → 최종 결과
공통 기록: 각 단계의 입력·설정·코드·모델·출력·원본 연결·비용
비교: 실행 A + 실행 B + 평가 설정·정답 표본 → 차이·복구·퇴행·미해결 보고서
```

목표는 무엇을 바꿨고, 같은 근거를 어느 단계에서 복구하거나 잃었으며, 비용은 어떻게 달라졌는지 확인하는 것이다.
공통 기록 기능은 파싱 모듈 밖에 두고 이후 단계가 같은 구조에 연결되도록 설계한다.
첫 코드 구현 범위는 공통 기록·비교 기반과 파싱 어댑터 연결, 문장·위치·표 전후 평가다.
청킹·임베딩·인덱스·검색·리랭킹의 실제 알고리즘과 모델을 이 계획으로 미리 확정하지 않는다.
문장 복구량을 측정하는 코드와 문장을 실제로 수정하는 복구 알고리즘도 별개다.

### 기존 구현과 이번 설계의 경계

| 항목 | 현재 확인한 상태 | 이번 설계 |
|---|---|---|
| 실행 조건 | `run.py`가 패키지 버전·명시적 설정·선정 목록·파싱 코드 해시를 기록 | 전체 단계가 공유하는 기록과 세 종류의 설정 비교 |
| 실제 호출·기록 연결 | 어댑터의 `predict_options()`를 실제 호출과 기록에서 함께 사용 | 요청·해석·결과에서 관찰한 설정을 구분 |
| 소스 추적 | 파싱 코드 해시만 기록 | 실행 당시 소스·설정 복사본, Git commit·미커밋 diff |
| 규칙 검사 | 입력 해시·ID·좌표·반복·병합 그룹·표 격자 검사 | 기존 검사를 재사용하고 두 실행의 변경·품질·비용을 연결 |
| 원문 정확도 | 정성 관찰과 일부 구조 검사. 문장·셀 정답 표본 미작성 | 확인한 정답에 한해 복구·새 누락·위치·표 대응 계산 |
| 모델·자원 | 모델 가중치 revision 미확보, 경과 시간 기록 | 구성 모델별 파일 동일성과 출처, 구간별 메모리 기록 |

근거: [현재 실행 코드](../../parsing/run.py), [결과 변환](../../parsing/model_result.py),
[규칙 검사 실행](../../parsing/validate_run.py), [기존 문제 정리](../parsing_log/PARSING_REVIEW.md).
현재 데이터 범위·실행 횟수·검토 신호 수를 새 비교 기능의 검증 결과로 바꾸어 적지 않는다.

## 2. 비교 방식과 통제 조건

| 방식 | 고정하거나 추적할 조건 | 판단할 내용 |
|---|---|---|
| 단계 자체 비교 | 같은 입력 결과물을 재사용하고 지정한 단계의 변수만 변경 | 그 단계의 동작·품질·비용 변화 |
| 전체 실행 비교 | 두 실행의 모든 변경 조건과 단계별 연결을 기록 | 최종 검색 효과와 그 과정에서 관찰한 정보 변화 |

예를 들어 리랭커 자체를 비교할 때는 질의·후보 ID·후보 내용·후보 수·입력 잘림 조건을 고정한다.
파싱부터 다시 실행해 후보까지 달라졌다면 전체 실행 비교로 표시하고 리랭커 하나의 인과 효과로 보고하지 않는다.
실험마다 바꿀 변수·고정 조건·기대 효과·반증 조건을 설정으로 받는다.
설정 차이를 자동 계산해도 변경 이유까지 추론하지 않으며, 입력받은 설명은 작성한 실험 의도로 표시한다.

비교 전에 문서·페이지 범위, PDF 해시, 모델 입력 해시, DPI·전처리, 평가 단위·정답 버전을 확인한다.
비교 대상 전체와 양쪽에 공통으로 있는 범위, 추가·제외·실패한 항목을 모두 보고한다.
공통 성공 페이지만 골라 품질을 높게 보이게 만들지 않는다.

입력 차이가 있으면 항목별 비교 가능 여부와 이유를 남긴다.
같은 PDF의 DPI를 실험 변수로 바꾼 경우 모델 입력 이미지는 달라졌다고 기록하되,
같은 원문 정답과 PDF 좌표로 문장·위치를 평가할 수 있다. 해상도가 다른 이미지 픽셀을 바로 비교하지 않는다.
원본 PDF나 정답 버전이 달라진 항목은 동일 입력의 품질 전후 비교에서 분리한다.

이전 단계 결과를 재사용하면 원본 실행·단계·결과물 해시를 연결한다.
재사용한 결과에 현재 코드·모델로 새로 계산했다는 기록을 붙이지 않는다.
질의·관련성 라벨·정답 문장은 평가 입력으로 분리하고 검색용 문서 표현이나 인덱스에 섞지 않는다.

## 3. 공통 실행·단계·결과물 기록

아래 필드와 상태는 앞으로 구현할 제안 스키마다. 현재 실행 JSON에 존재한다는 뜻이 아니다.

| 단위 | 주요 정보 | 역할 |
|---|---|---|
| 실험 | 목적·변경 변수·고정 조건·기준/비교 실행 참조 | 비교 질문과 실행을 묶음 |
| 실행 | `run_id`, 스키마 버전·시각·환경·코드·실행 의도 | 한 실행의 조건과 수명 주기 식별 |
| 단계 실행 | `stage_run_id`, 단계 이름·상태·입력/출력 참조·평가·자원 | 한 단계의 계산 또는 재사용 추적 |
| 결과물 | `artifact_id`, 종류·경로·크기·내용 해시·생성 단계 | 파일·레코드·벡터 묶음의 동일성 확인 |
| 원본 연결 | 원본 PDF 해시·페이지·영역, 입력 요소와 출력 요소의 관계 | 블록·청크·벡터·후보의 원문 근거 추적 |
| 평가 | 정답·지표·정규화·매칭 설정의 버전과 해시 | 점수 정의와 분모 재현 |

실행 ID는 내용 해시와 구분한다. 같은 입력을 반복 실행해도 서로 다른 실행을 기록한다.
원본 파일명에서 만든 프로젝트 ID를 공식 데이터셋 ID로 취급하지 않는다.
상태는 시작·완료·부분 실패·실패·중단·재사용을 구분하고, 실패 단계와 확보한 결과를 보존한다.
수집할 수 없는 항목은 값과 함께 수집 상태·미확인 이유를 남긴다. 누락·명시적 null·0은 다르게 취급한다.

### 파일 보존과 종료 처리

다음은 새 기록의 논리적 구성이다. 실제 출력 루트·경로는 실행 인자로 받는다.

| 기록 | 저장 내용 |
|---|---|
| 시작 manifest | 요청 설정·입력 참조·코드 상태·시작 시각 |
| 단계 manifest | 입력·해석/관찰 설정·결과물·모델 목록·종료 상태 |
| 소스 복사본과 목록 | 수집한 프로젝트 소스·설정의 실제 bytes와 해시 |
| 모델 파일 목록 | 구성 모델별 출처·revision·파일 해시 |
| 자원 측정 기록 | 시각·단계·프로세스별 관측값과 수집 상태 |
| 원본 연결 목록 | 이전 단계 결과·원본 위치와 파생 요소의 연결 |
| 비교 JSON·Markdown | 기계 판독용 상세 결과와 검토용 요약·근거 링크 |

시작 기록과 종료 요약을 나누고 기존 파일을 묵시적으로 덮어쓰지 않는다.
정상 예외는 종료 처리에서 기록하고, 강제 종료·OOM으로 종료 처리까지 못 간 실행은
남은 기록으로 중단 상태를 판단한다. 종료 요약이 없는데 완료로 간주하지 않는다.
보고서는 두 입력 실행 폴더 밖의 새 출력 위치에 생성한다.
평가·기록 스키마 변경 시 버전을 올리고 기존 결과를 다시 쓰지 않는다.

## 4. 설정 차이 자동 보고

설정은 다음 세 층을 별도로 수집한다.

| 설정 층 | 수집 위치·방법 | 한계 |
|---|---|---|
| 요청 설정 | CLI·설정 파일·어댑터가 실제 전달한 값 | 생략한 라이브러리 기본값은 포함하지 않음 |
| 해석된 설정 | 해당 버전이 제공하는 설정 내보내기 기능과 초기화 결과 | 내보낸 설정이 모든 런타임 적용값을 설명한다고 단정하지 않음 |
| 관찰한 설정 | 페이지 결과의 `model_settings` 등 반환값 | 반환되지 않는 디코딩 값이나 모델 내부 상태는 미확인 |

설치된 PaddleOCR 3.7.0의 파이프라인 래퍼에는 `export_paddlex_config_to_yaml()`이 있다.
해당 버전의 어댑터에서 이 기능을 활용하고, 이후 라이브러리가 바뀌면 지원 여부를 다시 검사한다.
페이지마다 관찰 설정이 다르면 실행 대표값 하나로 덮지 않고 페이지별 값과 충돌을 남긴다.

비교는 중첩 객체를 설정 경로별로 펼쳐 값 변경·키 추가·키 삭제·타입 변경을 계산한다.
객체 키 순서는 무시하되 순서가 의미 있는 목록은 그대로 비교한다.
측정 시각·출력 위치 같은 운영 정보와 품질에 영향을 주는 설정을 구분해 보여준다.
각 차이에 원본 파일·필드 경로와 요청/해석/관찰 중 어느 근거인지 연결한다.
기본값의 차이를 확인하지 못하면 동일하다고 표시하지 않는다.

## 5. 코드 diff·실험 의도·환경 기록

실행 시작 시 Git commit, 브랜치, 미커밋 변경 여부, 수집 대상 소스·설정 복사본과 해시를 기록한다.
staged·unstaged diff와 미추적 파일 목록도 수집 범위 안에서 남긴다.
추적 중인 파일뿐 아니라 실행에 사용하는 미추적 파일도 명시한 수집 범위 안에서 포함한다.
파일이 수집 중 바뀌거나 실행 중 코드가 수정된 정황이 있으면 재현성 경고와 범위를 기록한다.
필요 시 복사본에서 실행하는 방식은 실제 실행 환경을 확인한 뒤 선택하며, 복사만으로 실제 실행 파일이 고정됐다고 보지 않는다.

두 실행에 보관한 복사본끼리 `difflib`의 unified diff를 만들어 파일 추가·삭제·내용 변경을 보고한다.
Git diff는 실행 당시 작업 상태의 보조 근거이고, 실행 간 비교는 보관한 bytes를 기준으로 한다.
Git이 없는 환경도 소스 복사본과 해시로 비교할 수 있게 한다.
설치 라이브러리는 패키지 버전과 기록 어댑터가 의존하는 구현 파일의 해시·수집 범위를 남긴다.

경로·모델 ID·revision·샘플링 간격·임계값·후보 수·가중치는 설정 파일이나 실행 인자로 받는다.
기본값이 필요하면 한 곳의 이름 있는 상수로 두고 의미·단위·선정 이유를 설명하며 적용값을 기록한다.
문서명·페이지·질의별 예외 분기와 관찰 결과를 그대로 반환하는 처리는 만들지 않는다.
토큰·비밀번호·API 키는 복사본·Git diff·설정·환경 기록·보고서에 넣지 않는다.
수집 파일·환경 필드를 제한하고 비밀이 포함된 항목은 안전한 수집이 확인될 때까지 보류하며 누락 사유를 남긴다.

기존 실행의 코드 해시는 파일 내용이 아니다. 과거 Git 파일의 bytes와 해시가 일치하는 경우에만 복원 근거로 쓰고,
찾지 못하면 소스 미확보로 남긴다. 현재 코드를 과거 실행 코드로 대신 사용하지 않는다.

## 6. 구성 모델별 가중치 revision과 파일 동일성

파이프라인 이름 하나 대신 실제 로딩한 구성 모델별 manifest를 만든다.
파싱에서는 VL·레이아웃·문자 검출/인식·표 구조·셀 검출·수식·차트 등을 구분한다.
임베딩·리랭킹에서도 같은 모델 기록 구조를 사용한다.

| 항목 | 기록 방법 |
|---|---|
| 역할·식별자 | 단계·모듈 역할·모델 이름·실제 로딩 경로를 버전별 어댑터에서 확보 |
| 출처·revision | 확인한 저장소 ID·요청 revision·해석된 전체 commit과 확인 근거 |
| 파일 동일성 | 가중치·설정·토크나이저 등 필요한 파일의 상대 경로·크기·SHA-256 |
| 수집 상태 | 확인 완료·일부 확보·미확인·실패와 이유 |
| 실행 범위 | 로딩된 모델과 특정 페이지에서 호출이 관찰된 모델을 구분 |

캐시 폴더에서 가장 최근 파일을 찾아 실제 사용 모델이라고 추정하지 않는다.
역할별 실제 경로를 확보하지 못하면 실행 설정에서 요청한 모델과 실제 파일 확인 상태를 나눠 기록한다.
파일 해시는 출처 revision을 대신하지 않는다. 공식 commit을 모르는 파일도 해시로 동일성을 비교할 수 있다.
모델 목록 해시는 파일 내용 해시의 정렬된 목록으로 계산하고 절대 경로·캐시 시각을 동일성 기준에 섞지 않는다.
큰 가중치는 나눠 읽어 해시를 계산하고 모델별 수집 시간을 기록한다.

설치된 PaddleX 3.7.2의 기본 Hugging Face 다운로드 경로는 `snapshot_download()`에 revision을 명시하지 않는다.
revision 고정이 필요한 실행은 확인한 전체 commit으로 확보한 로컬 경로를 모델 설정에 연결하고,
실제 로딩 경로와 파일 목록을 다시 대조한다. 라이브러리 패키지 버전만으로 가중치 revision을 고정했다고 보지 않는다.
추가 다운로드·모델 경로 변경은 실제 구현·실행 범위에서 별도로 다루고 이 문서 작성 중에는 수행하지 않는다.

근거: [PaddleOCR v3.7.0 설정 내보내기](https://github.com/PaddlePaddle/PaddleOCR/blob/v3.7.0/paddleocr/_pipelines/base.py),
[PaddleX v3.7.2 모델 확보 경로](https://github.com/PaddlePaddle/PaddleX/blob/v3.7.2/paddlex/inference/utils/official_models.py),
[Hugging Face revision 지정](https://huggingface.co/docs/huggingface_hub/guides/download).

## 7. 시간·메모리·호출 비용 기록

현재 설치된 `psutil`을 실제 구현에서 직접 의존성으로 명시하고 프로세스 RSS를 주기적으로 수집한다.
Python 객체만 추적하는 메모리 값으로 Paddle·NumPy의 전체 사용량을 대신하지 않는다.
샘플링 간격·자식 프로세스 포함 정책·GPU 수집 여부는 설정으로 받는다.

| 기록 | 구분할 내용 |
|---|---|
| CPU 메모리 | 주 프로세스와 자식 PID별 RSS, 시작·종료·관측 최대값, 샘플 수·간격 |
| GPU 메모리 | 장치와 수집 API가 지원하는 경우 별도 기록. 프레임워크 할당/예약량과 장치 전체 사용량의 범위를 구분 |
| 시간 | 모델 로딩·PDF 읽기·렌더링·추론·변환·저장·검사·전체 실행 |
| 관측 부대비용 | 소스 수집·가중치 해시·모니터링·보고서 생성 시간 |
| 모델 호출 | 단계·호출 수·실패·재시도, 확인 가능한 토큰·이미지 입력량 |
| 비용 | 실제 청구 근거 또는 단가·적용 시점·단위를 명시한 추정값. 미확인 비용은 null |

주기적 측정값은 관측 최대값이며 짧은 순간의 최고점을 놓칠 수 있다.
자식 프로세스 RSS 합계에는 공유 메모리가 중복될 수 있어 고유한 실제 사용량으로 표시하지 않는다.
모델 상주 메모리가 있으므로 종료−시작 차이만으로 페이지 비용을 평가하지 않는다.
권한 부족·프로세스 종료·미지원 GPU는 0으로 채우지 않고 수집 실패·미측정을 기록한다.
수집 실패가 본래 추론 실패로 바뀌지 않도록 분리하되, 메모리 측정이 실험 필수 조건이면 조건 미충족을 보고한다.
강제 종료 이전의 샘플도 남길 수 있도록 점진적으로 기록하고 완전한 최고점 확보는 보장하지 않는다.
GPU 비동기 실행의 시간 경계는 지원 장치에서 동기화 여부와 영향을 명시한다.

하드웨어·운영체제·장치·스레드·워밍업·반복 횟수·페이지 순서·캐시 조건·시드를 기록한다.
시드가 있어도 완전한 결정성을 보장하지 않는다. 품질 차이와 실행 변동성을 구분하고,
비용 비교 시 측정 조건과 관측 부대비용 포함 여부를 함께 표시한다.
메모리 API와 지원 환경은 [psutil 7.2 문서](https://psutil.io/7.2/#psutil.Process.memory_info)를 기준으로 확인한다.

## 8. 정답 표본·원본 연결·매칭

현재 문장 전사·문장 위치·표 셀 정답은 작성하지 않았다.
평가 엔진과 스키마 검증은 모의 입력으로 먼저 구현할 수 있지만, 실제 정확도는 원문을 대조해 확인한 표본으로 계산한다.
native 텍스트·기존 OCR·검토 모델은 정답 초안의 참고 자료이며 원문 확인 전에는 정답으로 승격하지 않는다.

| 정답 유형 | 필요한 정보 |
|---|---|
| 공통 출처 | 정답 버전·해시·문서 PDF 해시·페이지 기준·확인 상태·검토 근거 |
| 문장 | 출력 ID와 독립적인 정답 ID, 확인한 원문·허용 표기 차이·위치 목록 |
| 위치 | 좌표계·단위·회전 기준, 문장 또는 줄 영역 목록·매칭 허용 기준 |
| 표 | 정답 표 ID·위치, 행·열·병합 범위·헤더 경로·셀 내용·필요한 셀 위치 |
| 검색 | 질의·관련성 레이블·분할·평가 단위·중복 판정 규칙 |

정답 범위에는 정상·오류 사례를 함께 포함하고 판단 보류·미판정·분모·표본 커버리지를 보고한다.
이미 관찰한 페이지는 개발·회귀 표본으로 다루며 최종 평가용 문서를 분리한다.
알려진 실패 표본만으로 전체 오류율을 추정하지 않고 최종 평가 라벨로 임계값을 반복 조정하지 않는다.

출력 목록 순번이나 청크 ID가 같다는 이유만으로 같은 근거로 연결하지 않는다.
원본 PDF·페이지·영역을 기준으로 파싱 요소 → 청크 → 벡터 → 후보 → 최종 순위를 연결한다.
분할·병합에 따른 일대다·다대일 관계, 원본 구간·이미지 crop·문자 offset의 기준을 보존한다.
원본 연결은 대응 후보의 근거이며 내용 정확성의 증명은 아니다.

문장 매칭은 같은 페이지의 출력 문자열에서 내용 대응을 먼저 찾고 위치는 그 뒤 평가한다.
정답 bbox 안에서만 문장을 찾으면 잘못 배치한 문장을 단순 누락으로 오판할 수 있다.
기본 정규화는 NFC·공백 처리처럼 의미 보존 범위를 명시하고 숫자·부호·첨자를 임의로 없애지 않는다.
정확 일치·부분 일치·불일치·누락·모호한 대응을 구분하며 허용 규칙·임계값을 기록한다.
반복되는 같은 문장, 여러 블록에 걸친 문장, 병합 그룹은 소비한 출력 구간과 여러 위치를 남겨 중복 채점을 막는다.
대응을 유일하게 결정하지 못하면 임의로 가장 가까운 블록에 붙이지 않고 미해결로 남긴다.

## 9. 문장 복구·새 누락·위치 정확도

원문 확인을 마친 같은 정답 문장 집합을 T, 실행별 정확히 복구했다고 확인한 집합을 C_A·C_B로 둔다.
부분 일치의 점수와 정확 복구 판정을 분리한다. 다음은 프로젝트에서 구현할 지표 정의다.

| 지표·판정 | 정의·처리 |
|---|---|
| 확인된 문장 복구율 | 실행별 정확 복구 문장 수 / T의 문장 수 |
| 복구 | B에서 정확 복구됐고 A에서는 실패가 확인된 문장 |
| 새 누락 | A에서 정확했고 B에서는 대응 내용이 없는 것으로 확인된 문장 |
| 새 오인식 | A에서 정확했고 B에는 대응 내용이 있으나 틀린 문장 |
| 계속 실패 | 양쪽에서 누락·오인식이 확인된 문장 |
| 판정 보류 | 한쪽이라도 대응이 모호하거나 판정 근거가 부족한 문장 |
| 위치까지 복구한 비율 | 내용과 위치가 모두 맞는 것으로 확인한 문장 수 / T의 문장 수 |
| 내용 일치 문장의 위치 결과 | 내용이 맞는 문장 안에서 위치 일치·불일치·미해결을 추가 집계 |

판정 보류가 있으면 확인된 복구율은 보수적인 확인 범위의 값임을 표시하고 보류 수·비율도 함께 보고한다.
미해결을 새 누락이나 복구로 확정하지 않는다. 분모가 0이면 null과 이유를 남긴다.
실행 실패로 예정된 페이지 결과가 없으면 실패 원인과 누락을 보고하고 해당 페이지를 평균에서 숨기지 않는다.

위치는 공통 PDF 좌표에서 정답 영역과 출력 영역 목록을 비교한다.
IoU 등 공간 지표와 허용 오차·영역 결합 규칙을 설정으로 받고, 큰 bbox에 정답이 들어간 사실만으로 통과시키지 않는다.
블록 bbox만 있으면 블록 수준의 대리 지표로 표시하며 정밀 문장 위치로 주장하지 않는다.
병합된 두 단의 내용을 한 블록에 붙인 경우 내용 복구와 위치 실패·미해결을 별도로 남긴다.
필요한 문자/단어 오류율을 추가할 때는 편집거리·정규화·분모 정의를 명시하고 주 판정과 분리한다.

## 10. 표 셀 내용·행·열·헤더 대응

기존 HTML 격자 검사를 재사용해 rowspan·colspan을 반영한 논리 격자를 만든다.
격자가 정상이라는 사실과 셀 내용·배치가 정확하다는 판정을 분리한다.
정답 표와 출력 표를 원본 위치·표 식별 근거로 연결한 뒤 셀 배치·내용·헤더를 평가한다.

| 평가 | 측정할 내용 |
|---|---|
| 표 검출·누락 | 정답 표를 찾았는지, 불필요한 표가 생겼는지 |
| 셀 내용 | 문자·숫자·음수 괄호·소수점·단위·기호의 일치 |
| 셀 배치 | 올바른 행·열에 있는지, 다른 행으로 이동했는지 |
| 헤더 관계 | 다단 헤더·행 키와 값의 연결 |
| 병합 구조 | rowspan·colspan과 빈칸·아이콘 셀 구분 |
| 전후 변화 | 복구·새 누락·새 이동·새 오인식·미해결 |

숫자가 페이지 어딘가에 존재해도 올바른 행·열·헤더의 값으로 연결되지 않으면 셀 대응 성공이 아니다.
빈칸·대시·0을 통일하지 않고 허용할 표기 차이는 평가 설정에 둔다.
원본 셀 위치·Structure의 셀/OCR 목록·HTML 셀의 순서가 같다고 가정하지 않는다.
표 전체가 빠지거나 파싱에 실패한 경우도 정답 표·셀 분모에서 유지하고 대응 실패 원인을 남긴다.
일부 셀만 확인한 표본이면 평가한 범위·셀 수와 미판정 수를 표시하고 표 전체 정확도로 확대하지 않는다.

## 11. 후속 단계로의 확장

| 단계 | 추가할 단계별 기록 | 전후 비교 |
|---|---|---|
| 청킹 | 경계·길이·겹침·원본 구간·헤더/주변 문맥·상위 문서 연결 | 필요한 근거 보존, 경계에서 끊긴 조건·예외, 중복·청크 수·길이 |
| 임베딩 | 모델·revision·질의/문서 입력·프롬프트·전처리·토큰 잘림·차원·정규화·벡터 ID | 인코딩 비용·잘림과 동일 근거의 검색 품질 변화 |
| 인덱싱 | 입력 벡터 목록·모델·거리 함수·인덱스 설정·필터·구축 비용 | 같은 벡터·거리·범위의 Exact Search 대비 ANN 누락·비용 |
| 후보 생성·확장·결합 | 경로별 후보·확장 관계·공통 단위 매핑·점수·후보 예산·결합 설정 | 단계별 정답 포함·누락·중복·무관한 후보 유입 |
| 리랭킹 | 질의·후보 ID와 실제 입력 내용·잘림·모델·점수·전체 순위 | 같은 후보의 정답 순위 상승/하락, Top 3 진입/이탈, 비용 |
| 최종 평가 | 질의·관련성 라벨·평가 단위·중복 정책·반환 길이·실패 | Recall@1·@3·@10, 혼입·퇴행 질의와 전체 비용 |

다른 모델의 임베딩은 차원이 같아도 좌표를 직접 빼거나 모델 간 내적으로 비교하지 않는다.
모델마다 자기 질의·문서 표현을 비교하고 같은 원본 평가 단위·정답·검색 범위에서 검색 품질을 비교한다.
ANN 재현과 정답 근거 검색 품질은 별개다. 새 검색 방식은 검색 예산을 늘린 기준선과도 비교한다.
리랭킹 비교는 후보 밖의 정답이 새로 복구됐다고 주장하지 않고 후보 자체의 변경을 별도로 보고한다.

검색 지표의 정의·분모·macro 집계·빈 정답·실패 질의·반환 길이·최종 Top 3와 평가용 순위의 관계는
[프로젝트 계획](PROJECT_PLAN.md)의 평가 정의를 따른다. 지표 정의와 평가 설정의 버전·해시를 기록한다.
공식 MMDocIR 지표를 확인하기 전에는 이 결과를 공식 벤치마크 재현이라고 표시하지 않는다.

단계별 정보 손실은 원본 근거의 연결과 실제 평가 근거가 있는 구간에서만 판단한다.
관측이 없는 구간은 미확인으로 남기고, 처음 확인되는 손실 위치와 확정한 원인을 구분한다.

## 12. 보고서 구조와 호환성

보고서에서는 다음을 같은 평가 범위에서 읽을 수 있게 한다.

1. 실험 목적·기준/비교 실행과 비교 방식.
2. 입력·평가 범위의 차이, 비교 가능 항목·불가능 항목과 이유.
3. 설정·코드·모델·가중치 파일의 변경.
4. 단계별 결과·복구·새 누락·새 오인식·위치·표 대응·미해결.
5. 후속 단계가 구현된 범위의 후보·순위·최종 검색 효과.
6. 시간·메모리·호출·비용 차이와 측정 조건.
7. 원본·결과물·정답·diff·매칭 근거 링크와 수집 누락.

JSON에 상세 기록을 저장하고 Markdown은 같은 데이터에서 생성해 수치가 어긋나지 않게 한다.
점수와 차이에는 방향·분자·분모·해당 표본 수·평가 조건을 함께 둔다.
임의의 가중 평균으로 파싱·검색·비용을 하나의 종합 점수로 합치지 않는다.

기존 `project.parsing.v1`·규칙 검사 결과는 읽기 전용 어댑터로 수용한다.
없는 소스·메모리·revision·정답은 미확보 상태로 유지하며, 새 필드를 과거 기록에 채워 넣지 않는다.
기존 실행에 문서별 추가 페이지 실행 기록이 있으면 페이지별 실행 출처를 우선 확인한다.
실행 루트 `run.json`·`summary.json`을 추가 실행까지 포함한 새 전체 기록으로 해석하지 않는다.
기존 실행도 입력·설정·확인 가능한 출력 차이는 보고하고, 근거가 부족한 코드 diff·정확도·비용은 미측정으로 남긴다.

## 13. 모듈 책임과 다음 코드 구현 범위

공통 모듈은 파싱 폴더 밖의 `experiments` 패키지에 구현했다. 공통 입출력·보안 처리는 `common.py`로 분리했다.
아래 책임 구분과 이후 확장 목표를 유지하며 현재 연결·평가 한계는 사용법을 기준으로 확인한다.

| 역할 제안 | 책임·입출력 |
|---|---|
| `experiments/record.py` | 설정·코드·환경·모델 manifest·원본 연결을 받아 공통 실행 기록 생성 |
| `experiments/resources.py` | 구간 시작/종료와 측정 설정을 받아 자원 관측·실패 기록 반환 |
| `experiments/evaluate.py` | 두 실행의 결과·정답·평가 설정을 받아 문장·위치·표 대응 평가 |
| `experiments/compare.py` | 입력 실행 조회·호환성 검사·설정/소스 diff·평가 조합·JSON/Markdown 저장을 담당하는 실행 진입점 |
| 파서별 어댑터 | 라이브러리 버전별 설정·실제 모델 경로·반환값을 공통 구조로 연결 |
| 기존 `run.py`·검사 코드 | 실제 단계 호출과 기존 규칙 검사. 공통 기록에 필요한 시점을 전달 |

수집 로직과 순수 비교·평가 함수를 분리하고 비교 실행이 모델 초기화나 네트워크 호출을 요구하지 않게 한다.
기본 스키마·공통 파일 저장 기능은 중복 없이 공유하고 세부 모듈 분리는 구현 복잡도에 맞춰 조정한다.
현재 실행 명령은 사용법과 CLI 도움말에 있다. 후속 단계의 미구현 명령을 실행 가능한 것처럼 제시하지 않는다.

다음 코드 제시에서는 공통 기록·모델 파일 추적·메모리·비교 실행·파싱 평가를 포함한 현재 범위의 전체 설계와 코드를 먼저 보여준다.
아래 작업 구분은 내부 연결·검증 순서이며 기능 일부만 보여주고 나머지를 숨기는 학습 순서가 아니다.

| 작업 | 완료 기준 |
|---|---|
| 공통 스키마·과거 결과 읽기 | 필수 필드·버전·누락·부분 실패를 구분하고 기존 입력 불변 확인 |
| 실행 기록과 파싱 연결 | 요청/해석/관찰 설정, 소스 복사본·diff, 모델 출처·파일, 자원 구간이 실제 호출과 연결 |
| 파싱 전후 평가 | 정답을 입력받아 분할·병합·문장·위치·표의 복구와 퇴행·미해결을 계산 |
| 통합 비교 보고 | 모의 입력과 기존 결과로 두 실행의 차이를 JSON·Markdown으로 재현. 정답 없는 항목은 미측정 |
| 실제 효과 검증 | 확인한 정답·고정한 실행 조건에서 새 모델 실행을 받아 효과·퇴행·비용을 측정 |
| 후속 단계 연결 | 각 단계의 실제 구현 시 같은 기록 계약·원본 연결·평가 단위로 확장 |

## 14. 검증 사례와 판단 보류 항목

테스트 입력은 테스트 안에서 만들고 각 경계 조건을 명시한다. 실제 결과 파일의 경로·해시·개수를 기대 정답으로 고정하지 않는다.
기존 실행 파일은 별도 호환성 확인 자료이며 모의 입력 테스트와 구분한다.

| 검증 대상 | 의미 있는 사례 |
|---|---|
| 설정 비교 | 추가·삭제·타입 변경, 미기록과 null, 요청/해석/관찰 불일치, 페이지별 적용값 차이 |
| 소스·모델 | 미커밋·미추적 파일, Git 없음, 수집 중 파일 변경, 과거 소스 없음, 같은 모델명·다른 가중치, revision 미확보 |
| 매칭·분모 | 블록 분할·병합, 반복 문장, 잘못된 bbox, 페이지 누락·실패, 정답 없음·빈 분모·부분 판정 |
| 표 | 병합셀·빈칸·대시·0, 값의 행 이동, 다단 헤더, 표 전체 누락, 모호한 셀 대응 |
| 자원 | 자식 프로세스 종료, 권한 부족, GPU 미지원, 샘플 누락, 중단 실행·미완성 종료 기록 |
| 보고·보존 | JSON/Markdown 수치 일치, 입력 폴더 불변, 기존 파일 덮어쓰기 거부, 재사용 결과의 출처 |
| 단계 확장 | 모의 단계의 입력 재사용, 청크 ID 변화, 공통 평가 단위 매핑, 다른 후보 집합의 리랭킹 비교 구분 |

문장·표 정답 표본, 매칭·위치 허용 기준, 실제 실행 장치와 GPU 측정 가능 범위는 아직 미확인이다.
구현 시 설정과 스키마는 받을 수 있게 하되 정답·임계값·장치 정보를 추정해 실제 점수를 만들지 않는다.
정답을 확인하기 전에도 기록·diff·호환성·실패 처리·모의 평가 엔진은 검증할 수 있다.
실제 원문 정확도와 개선 효과는 확인한 정답 표본과 실제 전후 실행 결과가 모두 준비된 뒤 판단한다.
