# RAG 5단계 실무 실습 커리큘럼

각자의 데이터셋으로 문서 기반 RAG를 구축한다. 파싱부터 임베딩·DB 선정, 검색·리랭킹, 답변 생성과 Ragas 평가까지 실습한다. Top-k에 섞인 무관하거나 잘못된 자료가 답변에 미치는 영향도 확인한다.

## 5단계 구성과 4~6주 일정 예시

| 단계 | 기간 | 주요 실습 |
|---|---|---|
| 1 파싱과 정제 | 4일 | 원문 추출, 구조·출처 보존, 파싱 오류 분석 |
| 2 청킹·임베딩·DB 선정 | 5일 | 청킹 비교, 임베딩 2~3개와 DB 2개 비교 |
| 3 검색 튜닝과 리랭킹 | 5일 | 하이브리드 검색, 후보 수, 리랭킹, Top-k 오염 |
| 4 답변과 컨텍스트 구성 | 3일 | 근거 선택, 토큰 예산, 출처와 답변 유보 |
| 5 Ragas 평가와 개선 | 3일 | 질문 유형별 품질 비교와 실패 원인 분석 |

## 시작 전 데이터 확인

| 항목 | 확인할 내용 |
|---|---|
| 목적과 범위 | 답할 질문과 답하지 않을 범위 |
| 형식과 규모 | 파일 형식, 언어, 문서 수와 분량 |
| 구조와 품질 | 제목·표·이미지, 중복·누락·깨진 문자와 예상 난점 |
| OCR 필요 여부 | 텍스트층과 이미지 속 글자의 추출 품질, 적용·생략 이유 |

모두 5단계를 진행하되, OCR·표·시각 자료 처리는 데이터에 맞춰 선택한다.

- OCR: 텍스트가 정상 추출되면 생략한다. 스캔 페이지나 누락된 이미지 영역에만 적용하고, 기존 텍스트와의 중복을 확인한다.
- 표·그림: 해당 자료가 있으면 구조·단위·각주·연결 관계를 원본과 대조한다. 문자 인식과 표 구조·차트 해석은 구분한다.
- 구조화 질의: 정확한 필터·합계·집계가 핵심이면 SQL이나 구조화 조회·계산 경로를 검토한다.

## Step 1 파싱과 정제

- 텍스트층·읽기 순서·이미지 속 글자를 확인한다. 직접 파싱을 기본으로 하고, 부족한 영역에 OCR이나 레이아웃 처리를 적용한다.
- 어려운 구간에서 파싱·정제 방식 두 가지를 비교한다. OCR은 적용 전후를 비교하거나 생략 이유를 기록한다.
- 표·각주·그림 설명을 연결한다. 머리말·꼬리말 정제 시 조건이나 시행일이 함께 삭제되지 않는지 확인한다.
- 정제 결과를 원본 페이지·영역과 연결하고, 추출 실패나 수동 검토가 필요한 구간을 표시한다.

### 저장할 구조의 예시

| 대상 | 보존할 정보 |
|---|---|
| 공통 블록 | 문서 ID·버전·페이지·영역 좌표·유형·추출 방식·원문 참조 |
| 본문 | 제목과 절 계층, 읽기 순서, 문단 ID, 관련 각주와 그림 ID |
| 표와 셀 | 표 ID, 행·열 인덱스, 병합 범위, 헤더 경로, 값·단위·각주 |
| 중첩 표 | 부모 표·부모 셀 ID와 하위 표 ID의 연결 관계 |
| OCR·그림 | 인식 텍스트·원본 영역·방향·검토 상태, 그림 설명과 추출값 구분 |

### 데이터에 따라 선택하는 난점

| 사례와 실패 원인 | 확인하고 실험할 것 |
|---|---|
| 중첩 표: 평탄화하면서 하위 값의 소속 조건을 잃음 | 부모 셀·하위 표 관계를 보존하고, 계층형 JSON과 행별 문장 변환을 비교한다. |
| 병합 셀과 다단 헤더: 상위 분류가 값에 붙지 않거나 빈칸을 0으로 해석 | 병합 범위와 헤더 경로를 복원한다. 빈값·미기재·반복 생략을 구분하고 행별 헤더를 검증한다. |
| 표 안 세로쓰기: 90도 회전 글자와 세로 조판을 혼동 | 페이지·셀 방향을 구분하고 영역 자르기·방향 교정·읽기 순서를 시험한다. 세로 조판과 회전 글자를 구분한다. |
| 여러 페이지에 걸친 표: 다음 페이지의 헤더·단위·각주가 분리 | 인접 페이지의 열·제목을 대조하고, 연결 전후의 값·조건 보존을 확인한다. |
| 이미지 속 글자와 혼합 PDF: 본문만 읽거나 OCR 중복으로 같은 글자를 두 번 저장 | 이미지 글자 누락과 기존 텍스트 중복을 확인하고 영역 OCR·전체 페이지 OCR을 비교한다. |
| 저해상도 숫자와 다단 본문: 0/O·1/l·소수점 혼동 또는 읽기 순서 뒤섞임 | 해상도·기울기·대비·언어 설정을 비교하고 숫자·부정어·읽기 순서를 원본과 대조한다. |
| 차트와 업무 흐름도: 글자를 읽어도 축·범례·화살표 관계가 사라짐 | 문자 인식과 관계 해석을 분리한다. 추출한 값·축·범례·연결 관계를 원본과 대조한다. |

## Step 2 청킹·임베딩·DB 비교

검색 단위와 임베딩 모델을 데이터에 맞게 선정한다. 듀얼 인코더는 질문과 문서를 각각 인코딩해 벡터로 비교하는 구조이며, 가중치는 공유하거나 별도로 둘 수 있다.

### 청킹 실험

- 고정 길이와 구조 기반 분할을 비교한다. 청크를 원본과 연결하고 제목·조건·예외를 보존한다. 생성한 요약·질문은 원문과 구분한다.
- 크기 256/512/1024 토큰, 겹침 0/10/20% 등을 비교한다. 한 변수씩 바꾼 뒤 유망한 조합을 확인한다.
- 모델의 입력 한도와 토크나이저를 확인한다. 제목·헤더·지시문을 포함한 실제 입력의 잘림을 기록한다.

### 임베딩과 듀얼 인코더 실험

- 모델 2~3개를 같은 청크·질문·근거 라벨로 비교한다. 데이터 언어·도메인 용어·제품 번호·약어·부정 표현을 포함한다.
- 모델별 질문·문서용 프롬프트와 인코딩 방식을 적용하고 설정 누락의 영향을 비교한다.
- 모델마다 문서·질문을 다시 임베딩하고 인덱스를 분리한다. 차원이 같아도 다른 모델의 벡터를 섞지 않으며, 거리 함수·정규화를 기록한다.

### 비교할 지표와 선정 근거

| 비교 대상 | 기록할 내용 |
|---|---|
| 청킹 | 핵심 근거 보존, 청크 수와 길이, 중복, 입력 잘림 비율 |
| 검색 품질 | 근거 Recall@k, MRR, nDCG와 질문 유형별 결과 |
| 모델 비용과 제약 | 문서·질문 인코딩 시간, 저장 크기, 호출 비용, 입력 한도 |

같은 근거 라벨에 대한 검색 성능을 비교한다. 모델별 유사도 점수의 절대값은 직접 비교하지 않는다. 정확 벡터 검색을 기준으로 보면 임베딩 품질과 근사 인덱스의 누락을 구분하기 좋다.

### DB 2개 비교

| 항목 | 실습과 확인 내용 |
|---|---|
| 벡터와 거리 함수 | 같은 벡터·거리 함수·정규화·필터로 비교한다. 차원·모델·버전도 확인한다. |
| 정확 검색과 ANN | 정확 검색 결과를 보관하고, 근사 최근접 이웃 검색인 ANN의 누락과 시간 변화를 비교한다. |
| 메타데이터 필터 | 부서·버전·시행일 필터를 적용한다. 조건에 맞는 근거의 누락과 결과 개수를 확인한다. |
| 추가와 수정 및 삭제 | 같은 문서 재처리, 문서 개정, 삭제, 중단 후 재개를 실행한다. 중복과 오래된 청크 잔존 여부를 점검한다. |
| 저장과 재시작 | 저장 후 재시작해 문서 수와 검색 결과를 확인한다. 인덱스 생성 완료 여부와 설정 재현 방법을 남긴다. |

### 근거 검색 품질과 ANN 구분

- 근거 Recall@k: 필요한 정답 근거를 얼마나 찾았는지 확인한다.
- ANN 이웃 일치율: 동일한 필터·거리 조건에서 정확 벡터 검색의 상위 k개를 ANN이 얼마나 재현하는지 확인한다.
- k와 탐색량: 결과 개수 k와 HNSW 탐색량은 별개다. 한 변수를 고정하고 다른 변수를 바꿔 비교한다.
- ANN이 정확 검색을 잘 재현해도 정답 근거를 찾았다는 뜻은 아니다. 소규모 데이터에서는 전수 검색이 실행될 수 있으므로 실제 인덱스 사용 여부도 확인한다.

### 어려운 사례와 진단 과제

| 어려운 상황 | 확인할 것과 개선 실험 |
|---|---|
| 표 값은 검색되지만 의미가 없음 | 청크에 상위 헤더·행 이름·단위가 있는지 확인한다. 표 전체, 헤더를 붙인 행 단위, 요약과 원본 연결 방식을 비교한다. |
| 조건과 예외가 다음 청크에 있음 | 정답에 필요한 최소 근거 묶음을 표시한다. 문단 경계 분할, 겹침, 작은 청크 검색 후 부모 구간 확장을 비교한다. |
| 큰 청크의 끝부분이 인코딩되지 않음 | 모델 토큰 한도와 실제 전처리 입력을 확인한다. 자르기 정책과 제목·프롬프트 추가 후 잘림 비율을 기록한다. |
| 겹침 때문에 같은 근거가 상위를 독점 | 원본 구간과 중복 청크를 추적한다. 중복 제거 전후의 검색 다양성·근거 포함·토큰 비용을 비교한다. |
| 한국어 약어와 제품 번호 검색 실패 | 모델의 언어·도메인 적합성을 유형별로 본다. 제목·메타데이터 보강과 키워드 검색을 후속 실험으로 연결한다. |
| 모델 변경 후 검색 결과가 이상함 | 문서와 질문의 모델·차원·버전·입력 형식을 확인한다. 새 인덱스에 재임베딩한 결과와 비교한다. |
| 필터 적용 후 정답 근거가 사라짐 | 메타데이터 오류와 필터 의미부터 확인한다. 같은 필터의 정확 검색과 ANN을 비교해 인덱스 누락을 분리한다. |
| 문서 개정 후 신구 내용이 함께 검색됨 | 문서 ID·버전·청크 ID와 교체 정책을 점검한다. 새 버전 반영과 이전 청크 제거, 중단 후 재시작을 시험한다. |

## Step 3 검색 튜닝과 리랭킹

벡터 검색·하이브리드 검색·크로스 인코더 리랭킹을 비교하고, 정답 근거의 후보 포함 여부와 순위 변화를 확인한다.

### 후보 검색과 최종 전달 개수

질문 → Bi-encoder로 후보 50개 검색 → Cross-encoder로 재정렬 → 상위 5개 선택 → 출처·버전·중복 점검 → 토큰 예산 안에서 LLM에 전달

Bi-encoder는 미리 저장한 문서 벡터로 후보를 찾고, Cross-encoder는 질문과 각 후보를 함께 입력해 관련성을 계산한다. 리랭커는 후보 밖의 근거를 새로 찾지 못한다.

| 변수 | 실습 예시 | 확인할 내용 |
|---|---|---|
| 후보 수 k_retrieve | 20 / 50 / 100 | 근거 Recall@k, 후보 처리 시간과 리랭킹 비용 |
| 최종 수 k_context | 3 / 5 / 10 | 최종 근거 누락, 중복, 토큰 수와 답변 품질 |
| ANN 탐색량 | DB별 제공 설정 | 정확 검색 대비 이웃 일치율과 지연 |
| 리랭커 | 미적용 / 적용 | 동일 후보에서 MRR·nDCG와 근거 순위 변화 |

### 비교 실험

- 벡터 검색만, 벡터 검색과 리랭킹, 하이브리드 검색만, 하이브리드 검색과 리랭킹을 비교한다. 리랭킹 유무 비교에서는 같은 후보 집합을 사용한다.
- 후보 수를 바꿀 때 최종 전달 수를 고정하고, 최종 전달 수를 바꿀 때 검색·리랭킹 조건을 고정한다. Step 4에서 답변 영향까지 확인한다.
- 키워드와 벡터 결과의 결합 방식을 기록한다. 서로 다른 점수의 범위를 점검하고, 순위 결합 등 선택한 방식의 이유를 설명한다.
- 질문별 후보 포함 여부·리랭킹 전후 순위·최종 선택 여부를 저장하고, 대표 실패를 원문까지 추적한다.

### 어려운 사례와 진단 과제

| 실패 상황 | 진단과 실험 |
|---|---|
| 정답 근거가 후보 50개 밖에 있음 | 후보 Recall부터 확인한다. 파싱·청킹·임베딩·키워드 보완·필터·후보 수를 점검하고 리랭킹 튜닝과 구분한다. |
| 리랭킹 후 정답이 밀려남 | 같은 후보로 언어·도메인 적합성, 입력 잘림, 헤더와 예외의 누락을 확인한다. 모델이나 입력 표현 변경 전후를 비교한다. |
| 부정과 예외를 놓침 | 지원 대상과 지원 제외 같은 유사 문장을 대조한다. 질문의 조건·부정어와 관련 예외가 후보에 함께 들어왔는지 확인한다. |
| 모델 번호와 날짜를 혼동 | 유사 의미 검색과 정확 문자열 일치를 구분한다. BM25·메타데이터 필터 보완 후 다른 번호와 날짜의 혼입을 확인한다. |
| 같은 문서의 중복 청크가 상위를 채움 | 원본 영역별로 중복을 집계한다. 중복 제거와 근거 다양성 조정이 복수 근거 질문의 회수율에 미치는 영향을 비교한다. |
| 복수 문서 질문에 근거 하나만 검색됨 | 첫 정답의 높은 순위와 전체 필요 근거의 회수를 별도로 본다. 질의 분해·검색 병합은 추가 개선 실험으로 검토한다. |
| 구버전과 다른 부서 규정이 상위 | 질문 시점·부서와 메타데이터 정책을 확인한다. 검색 전 필터와 최종 근거 선택 기준을 명시하고 충돌 사례를 검토한다. |
| 점수 임계값으로 모두 걸러짐 | 모델·거리 함수·리랭커별 점수 의미를 확인한다. 점수를 정답 확률로 가정하지 않고, 개발용 라벨로 임계값을 검증한다. |

### Top-k 오염과 환각 구분

Top-k는 검색된 상위 문서나 청크를 뜻한다. 검색된 자료 자체의 오류와, 생성 답변이 근거 밖의 내용을 만드는 환각을 구분한다.

| 발생한 문제 | 원인과 우선 조치 |
|---|---|
| 무관하지만 비슷한 자료가 다수 | 표현 유사성과 질문의 대상·조건이 다른 경우이다. 관련성·메타데이터·필터·질의와 후보 순위를 확인한다. |
| 구버전과 틀린 FAQ가 상위 | 신뢰성과 적용 시점 문제이다. 공식 출처·시행일·부서·버전·충돌 정책을 확인한다. 리랭킹만으로 진위를 보장하지 않는다. |
| AI 생성 요약이나 기존 답변에 오류 | 원문 밖의 주장이 검색 자료로 재유입될 수 있다. 생성물 표시와 원문 연결을 보존하고 미검증 내용을 구분한다. |
| 원문은 맞지만 청크에 조건이 없음 | 헤더·부정·예외·단위가 분리된 경우이다. 구조 보강과 주변 또는 부모 근거 확장을 검증한다. |
| 근거는 충분하지만 답변이 내용을 지어냄 | 생성·추론·컨텍스트 사용 문제이다. 실제 전달 근거와 주장별 지원 여부, 프롬프트와 답변 검증을 확인한다. |

잘못된 근거를 충실하게 따라도 답은 틀릴 수 있다. 근거 충실도·사실 정확성·출처의 신뢰성을 구분한다.

### Top-k 오염 재현 실험

정답 근거가 확인된 질문으로 아래 조건을 비교한다. 실험용 오류 자료는 원본과 분리하고 주입한 오류를 표시한다.

| 조건 | 구성할 컨텍스트와 목적 |
|---|---|
| A 깨끗한 근거 | 질문에 필요한 정답 근거만 제공한다. 검색 이후 생성 단계가 답할 수 있는지 확인한다. |
| B 무관 자료 추가 | A에 주제는 비슷하지만 질문과 무관한 자료를 섞는다. 노이즈에 따른 답변 변화를 본다. |
| C 그럴듯한 오답 추가 | A에 구버전 FAQ나 조건이 다른 답을 섞는다. 출처·시점·조건을 구별하는지 확인한다. |
| D 근거 없음 | 정답 근거 없이 무관한 자료만 제공한다. 단정적 오답과 적절한 유보를 확인한다. |
| E 일부 근거만 | 필요한 근거 하나 또는 예외를 제거한다. 답할 수 있는 범위와 남은 불확실성을 구분하는지 본다. |
| F 같은 자료 순서 변경 | 내용은 같게 두고 정답 근거의 위치를 바꾼다. 순서와 토큰 잘림에 따른 차이를 확인한다. |

### 질의 이해와 검색 경로 선택

질의 재작성·분해가 필요한 유형을 골라 원래 질문의 결과와 비교한다. 대상·날짜·수량·부정 조건이 유지되는지 확인한다.

| 질문 유형 | 실습과 주의할 점 |
|---|---|
| 짧고 모호한 질문 | 대상·시점·조건이 충분한지 확인한다. 부족하면 확인 질문을 하거나 가정을 표시한다. |
| 대화의 후속 질문 | 그것·작년·같은 조건의 의미를 대화에서 복원해 독립 검색 질의로 만든다. 다른 사용자나 대화의 정보가 섞이지 않게 한다. |
| 복수 문서 비교 | 질문을 필요한 하위 근거로 나누어 검색하고 결과를 병합한다. 모든 하위 근거가 회수됐는지 별도로 확인한다. |
| 약어와 도메인 표현 | 원래 질문을 보존한 채 동의어·용어 보강 또는 질의 재작성을 비교한다. 번호·날짜·부정·수량 조건이 바뀌면 실패로 기록한다. |
| 정확한 합계와 집계 | 전체 레코드가 필요한 질문은 Top-k 청크만으로 충분한지 확인한다. SQL·구조화 조회·계산 경로를 선택 과제로 검토한다. |

## Step 4 답변과 컨텍스트 구성

검색한 근거를 토큰 예산 안에서 구성하고 답변과 출처를 생성한다. 근거는 충분한데 답변이 틀린 경우를 따로 진단한다.

### 실험

- 검색 없는 답변, 실제 검색 근거로 만든 답변, 사람이 지정한 정답 근거로 만든 답변을 비교한다. 정답 근거 입력은 원인 진단용으로만 쓰고 실제 검색 성능으로 보고하지 않는다.
- k_context를 3/5/10으로 바꾸고 실제 전달 청크와 토큰 수를 기록한다. 시스템 지시·질문·근거·출력에 필요한 예산을 나누고, 모델의 전체 컨텍스트 한도를 확인한다.
- 같은 근거에서 중복 제거·순서·표 헤더와 각주 연결 방식을 바꿔본다. 최종 전달된 자료가 답변에 필요한 조건을 모두 포함하는지 확인한다.
- 숫자·단위·조건·예외를 답변에 반영하고, 주요 주장에 문서·페이지·영역 출처를 연결한다. 답이 없는 질문의 유보와 답이 있는 질문의 과도한 유보를 함께 확인한다.

### 어려운 사례와 점검

| 상황 | 진단과 실험 |
|---|---|
| 표 숫자는 맞지만 대상·단위가 틀림 | 정답 근거와 실제 컨텍스트의 헤더·각주를 대조한다. 단위 변환과 계산이 필요하면 계산 과정을 별도 검증한다. |
| 구버전과 신버전의 결론이 충돌 | 질문 시점과 적용 범위를 명시한다. 충돌을 드러내는 답변과 근거가 부족할 때의 처리 규칙을 검토한다. |
| 문서를 인용했지만 주장을 뒷받침하지 않음 | 출처 존재 여부와 주장별 근거 일치를 구분해 검토한다. 페이지 전체보다 실제 관련 영역을 확인한다. |
| 자료가 길어져 예외를 누락 | 전달 순서·최종 개수·중복과 잘린 내용을 기록한다. 근거를 줄이거나 필요한 조건을 연결한 결과와 비교한다. |
| 이미지 속 숫자가 추출 단계에서 틀림 | 답변과 OCR뿐 아니라 원본 이미지까지 대조한다. 신뢰도가 낮은 추출값을 단정하지 않는 처리 방식을 검토한다. |

### 지식의 신뢰성과 접근 경계

가상 사용자와 문서로 출처·권한·문서 속 지시문 처리와 캐시 분리를 확인한다.

| 점검 항목 | 실습할 실패와 기대 결과 |
|---|---|
| 출처와 최신성 | 공식 문서·FAQ·AI 요약의 충돌을 만든다. 적용 시점과 원본 우선 정책을 기록하고 해결 불가능한 충돌을 표시한다. |
| 허용된 문서만 검색 | 사용자 A·B의 접근 가능 문서를 구분한다. 허용되지 않은 문서는 LLM 입력과 답변·인용에도 들어가지 않는지 확인한다. |
| 문서 속 지시문 | 문서에 이전 지시를 무시하라는 가상 문구를 넣는다. 검색 자료를 시스템 지시로 취급하지 않는지 점검한다. |
| 대화와 캐시 분리 | 다른 사용자의 대화·검색 결과·캐시가 섞이지 않는지 확인한다. 권한과 문서 버전 변경 시 캐시 유효성을 시험한다. |
| 출처 검증과 계산 | 주장별 출처가 실제 내용을 지원하는지 확인한다. 숫자·단위·집계는 필요한 데이터와 계산 경로까지 검토한다. |

### 답변 유보와 부분 답변 정책

- 근거 부족·자료 충돌·권한 부족·서비스 실패를 구분한다. 충분히 뒷받침되는 부분만 답하고 남은 부분을 표시하거나 확인 질문을 한다.
- 검색 점수 하나를 보편적인 정답 확률로 취급하지 않는다.
- 답이 있는 질문을 유보한 비율과 답이 없는 질문에 단정한 비율을 함께 본다. 모든 답을 유보해 환각만 줄어든 구성을 좋은 결과로 평가하지 않는다.

## Step 5 Ragas 평가와 개선

검색 지표·Ragas·원문 검토로 설정별 품질을 비교한다. 개선용 질문과 검증용 질문은 분리한다.

### Ragas 핵심 지표

| 지표 | 확인할 내용 | 이번 실습의 주요 입력 |
|---|---|---|
| Context Precision | 유용한 근거가 검색 결과 상위에 배치됐는가 | 질문·검색 결과·기준 답변 |
| Context Recall | 기준 답변의 핵심 사실을 검색 결과가 충분히 뒷받침하는가 | 검색 결과·기준 답변 |
| Faithfulness | 생성 답변의 주장이 실제 제공한 근거로 뒷받침되는가 | 검색 결과·생성 답변 |
| Response Relevancy | 답변이 질문의 의도에 적절하게 응답하는가 | 질문·생성 답변 |

Context Precision은 기준 답변을 쓰는 방식으로 실습한다. 지표별 입력과 설정은 설치한 Ragas 버전에 맞춰 확인한다.

### 사실 정확성과 노이즈 내성

Top-k 오염 실험에는 Factual Correctness와 Noise Sensitivity를 추가한다.

| 평가 | 의미와 입력 |
|---|---|
| Factual Correctness: 높을수록 좋음 | 생성 답변과 기준 답변의 사실적 일치를 비교한다. response와 reference를 사용하며 precision·recall·F1 등의 설정을 기록한다. |
| Noise Sensitivity: 낮을수록 좋음 | 관련 또는 무관 근거를 활용해 생긴 잘못된 주장에 대한 민감도를 평가한다. 질문·기준 답변·생성 답변·검색 컨텍스트와 mode를 기록한다. |
| 오염 전후 정확성 변화 | A 깨끗한 근거 대비 B·C 오염 조건의 정답 유지와 악화를 비교한다. 이 변화량은 Ragas Noise Sensitivity 자체와 다른 별도 실험 결과이다. |
| 사람 검토 | 조건·단위·예외·원문 셀과 이미지·인용의 실제 일치를 확인한다. 잘못된 기준 답변도 검토 대상으로 둔다. |

### 답변 가능 여부별로 따로 보기

- 답변 가능한 질문: 핵심 사실 정확성, 필요한 사실의 완전성, 근거 충실도, 인용 일치, 불필요한 유보를 함께 확인한다.
- 답이 없는 질문: 근거 없는 단정, 적절한 유보·확인 질문을 확인한다. 기준 답변과 근거가 없는 사례에 적용 불가 지표를 무리하게 계산하지 않는다.
- 부분 근거와 충돌 질문: 가능한 부분만 답했는지와 불확실성 표시가 타당한지 본다. 모든 질문을 완전 정답 또는 완전 유보로만 나누지 않는다.

### 해석과 선정

- Faithfulness는 제공된 근거에 대한 충실도이다. 틀린 근거를 그대로 따라 사실 정확성이 낮은 답변도 나올 수 있다.
- Factual Correctness 또한 기준 답변의 품질에 의존하므로 정답 근거를 검증한다.
- 전체 평균과 함께 질문 유형별 결과·문항 수·평가 실패를 확인한다. 작은 점수 차이는 원문 검토와 반복 평가로 해석한다.

### 평가의 함정과 원인 분리

| 평가에서 어려운 상황 | 확인하고 실험할 것 |
|---|---|
| Faithfulness는 높은데 답은 틀림 | 잘못된 OCR·구버전·오류 문서에 충실한 답일 수 있다. 기준 답변, 실제 원본, 조건과 단위를 함께 검토한다. |
| 기준 답변이 틀리거나 불완전함 | 정답 근거와 기준 답변을 교차 검토한다. 라벨 수정은 버전을 남기고 비교 대상 전체를 같은 라벨로 재평가한다. |
| 평가 모델의 판단이 흔들림 | 경계 사례를 반복 평가하고 사람 판단과 대조한다. 평가 모델·프롬프트·설정을 고정하고 작은 점수 차이를 과도하게 해석하지 않는다. |
| 오류와 빈 결과가 평균에서 빠짐 | 평가 실패·빈 컨텍스트·타임아웃·유보를 구분한다. 성공한 평가만의 평균과 전체 문항 수, 제외 사유를 함께 보고한다. |
| 표와 이미지 오류를 텍스트 평가가 놓침 | 추출된 텍스트끼리만 비교하지 않고 원본 셀·이미지 영역을 확인한다. 시각 근거가 필요한 문항의 별도 검토 기준을 둔다. |
| 평균은 올랐지만 특정 유형이 나빠짐 | 표·세로쓰기·이미지·복수 근거·답 없음 유형별 문항 수와 실패를 보고한다. 적은 문항의 결과에는 실제 사례를 함께 제시한다. |

### 처음 실패한 단계 찾기

| 관찰된 결과 | 우선 확인할 단계 |
|---|---|
| 원본의 사실이 정제 데이터에 없음 | 파싱과 OCR 및 구조 복원 |
| 정제 데이터에는 있으나 청크에서 관계가 끊김 | 청킹과 메타데이터 연결 |
| 청크에 있으나 정확 벡터 검색도 못 찾음 | 임베딩·질의 표현·키워드 보완 |
| 정확 검색에는 있으나 ANN에서 빠짐 | 인덱스·탐색량·필터 조건 |
| 후보에는 있으나 최종 근거에서 빠짐 | 리랭킹·중복 제거·컨텍스트 선택 |
| 최종 근거는 충분하나 답변이 틀림 | 프롬프트·생성·계산과 인용 |

## 선택 실습: 갱신과 운영

- 문서를 추가·개정·삭제하고 중복 청크·구버전·캐시 잔존을 확인한다.
- 파싱·임베딩·색인을 중단 후 재개하고 누락이나 중복을 확인한다.
- 검색·리랭킹·LLM의 시간 초과와 호출 실패를 구분한다.
- 설정 변경 전후를 같은 질문으로 비교하고 이전 설정으로 복구해 본다.

## 실험 기록

질문 ID, 데이터·모델·설정 버전, 변경 변수, 검색 후보와 최종 컨텍스트, 답변, 품질 지표, 시간·토큰·비용, 실패 원인을 연결해 기록한다. 실행 방법과 데이터 출처도 함께 남긴다.
