# outputs 작업 지침

전체 규칙은 루트 AGENTS.md를 따른다. 여기에는 outputs/ 안에서만 쓰는 규칙을 적는다.

outputs/에는 실행이 만든 결과 폴더를 보관한다. 다음 단계 코드가 이 파일들의 해시로 입력을 확인하고,
docs의 기록이 실행 폴더를 링크한다. 그래서 한 번 만든 폴더는 고칠 수 있는 작업물이 아니라 기록으로 다룬다.

## 폴더

- 실행마다 코드가 새 폴더를 만든다. 이름은 `<단계>_<파서>_<UTC 시각>`이다.
  예: `parsing_vl_20261110T233124280038Z`, `chunking_structure_20261111T105933765387Z`,
  `rerecognition_vl_20261111T101144801007Z`
- `<실행 폴더>_comparison/`은 그 실행과 이전 실행을 비교한 보고서다(`experiments`의 자동 비교).
- 중단했다가 `main.py --resume`으로 이어 간 실행은 같은 폴더의 `resume/segment_<번호>/`에 재개 구간 기록이 쌓인다.
- 폴더와 파일 이름을 손으로 짓거나 만들지 않는다. 결과를 쓰는 코드는 이미 있는 폴더·파일을 덮어쓰지 않고 실패한다.

## 만든 뒤에는 고치지 않는다

- 결과 파일을 고치거나 지우거나 이름을 바꾸지 않는다. 편집기·포매터로 JSON을 다시 저장하는 것도 고치는 것이다.
- 이유는 두 가지다.
  - 다음 단계가 바이트 단위 해시로 입력을 확인한다. 청킹은 재인식 결과를 입력 실행 `run.json`의 해시가 같을 때만
    적용하고, 재인식은 페이지 JSON과 `source.pdf`의 해시를, 재개는 원본·코드 해시를 확인한다.
    한 바이트만 달라도 적용을 거부하거나 실행을 멈춘다.
  - docs의 기록이 실행 폴더와 그 안의 파일을 링크한다.
- 잘못된 결과도 지우지 않는다. 고친 결과는 새 실행으로 만들고, 두 실행의 차이를 docs의 기록에 적는다.
- 검사 보고서·재인식·청킹 같은 후처리 결과는 입력 실행 폴더 안에 쓰지 않고 새 폴더에 둔다.
  같은 폴더에 쓰는 것은 코드가 정한 재개(`resume/`)뿐이다.
- 과거에 3M 9페이지를 기존 VL 실행 폴더에 추가한 기록이 있다(`page_00009_run.json`). 그 기록은 그대로 두고,
  앞으로는 같은 방식으로 추가하지 않는다.

## 줄바꿈

- 결과 파일은 코드가 쓴 바이트 그대로 둔다. JSON은 LF 줄바꿈으로 저장되고, 기록된 해시도 그 바이트로 계산한 값이다.
- Windows에서 `core.autocrlf=true`로 저장소를 받으면 git이 LF를 CRLF로 바꿔 해시가 기록과 달라진다.
  실제로 청킹이 재인식 결과를 적용하지 못한 일이 있었다([구조 기반 청킹](../docs/chunking/CHUNKING.md) 6절).
- 줄바꿈이 바뀐 작업 사본에서는 해시를 확인하는 실행(청킹, 재인식, 재개, 실행 비교)을 하지 않는다.
  확인할 때는 파일의 SHA-256을 `run.json` 등에 기록된 값과 비교한다.

## 커밋

- 실행이 끝나 `summary.json`이 생긴 뒤 커밋한다. 중단된 채 커밋하면 기록 문서에 중단 상태와 이유를 적는다.
- 커밋하는 것: JSON, JSONL, PNG·JPG, 검토 PDF(`review_*.pdf`), 비교 보고서 Markdown.
- 커밋하지 않는 것: `source.pdf` 같은 원본 PDF. 루트 `.gitignore`의 `*.pdf` 규칙이 빼고, `review_*.pdf`만 다시 포함한다.
- 50MB를 넘는 파일은 커밋하지 않는다. GitHub는 50MB를 넘는 파일에 경고하고 100MB를 넘는 파일은 받지 않는다.
  일반 git에 한 번 넣은 파일은 나중에 지워도 이력에 남아 클론할 때마다 내려받게 된다.
  대신 그 실행의 기록 문서에 파일 경로, 크기, SHA-256, 실제 보관 위치, 요약이 든 파일을 적는다.
  예: `parsing_vl_20261110T233124280038Z/resume/segment_2/resources.jsonl`(88MB)은
  [병합 해제 재파싱 결과](../docs/parsing_log/REPARSE_RESULT.md) 2절에 이렇게 기록했다.
- 커밋하지 않은 큰 파일은 추적되지 않은 채 남는다. outputs/를 한꺼번에 스테이징할 때 파일 크기를 먼저 확인한다.
